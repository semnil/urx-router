# 既知の問題

現時点の制限事項の一覧。ルーティング規則の詳細は [device-model.md](device-model.md) を参照。

## CH → FX send の PRE/POST は実機へ反映できない

チャンネルから **FX 1 / FX 2** への send の PRE/POST は、プランナー上では自由に
編集でき (プランが意図する値を保持します)、software から URX へは書き込めません
(この設定は本体の操作パネル (LCD) からのみ変更できます)。そのため Live sync 接続中は
コントロールが読み取り専用になり、実機自身の値を表示します。

**Live sync 接続中に本体側で PRE/POST を変更した場合は、アプリに届きます**。実機が
変更を告知しており、アプリは書き込まないこのアドレスも購読しているためです。
コントロールは 1 秒程度で追従します。

以前はそうではありませんでした。同じ形が再発しうるので理由を残します: notify の
登録集合がアプリの発行するアドレスそのものだったため、読むだけのアドレスはどの登録
にも入らず、実機の告知が誰にも届いていませんでした。値が追いつくのは次の全体読みの
ときだけでした。実機にもプロトコルにも問題は無く、欠けていたのは登録だけです。

**CH → MIX** および **FX チャンネル → MIX** send の PRE/POST は従来どおり実機へ
反映できます。

> 背景: CH → FX send の PRE/POST は本体の操作パネルでのみ設定でき、broker は
> software からの書き込みを拒否します。

## CH SETTING の Icon は非対応

実機の CH SETTING には名前・色と並んで **Icon** の設定項目がありますが、プランナーでは
意図的に非対応としています。アイコンは mono チャンネルを含む全ノード種別が broker に
公開していますが、値がどの絵柄を指すかを示さない裸のグリフ ID であるため、対応するには
グリフ一式を実機画面と突き合わせて較正する作業が先に必要になるからです。名前と色は
値がそれ自体で意味を持つため対応しています。

## Multi-Band Compressor の Band Bypass は提供しない

実機のマルチバンドコンプレッサには 1 つのバンドに対する **Bypass** があるが、プランナーはこれを
提供せず、書き込みもしない。設定自体はエフェクトのエンジン上の単一の値だが、効く先は**実機側で
現在選択されているバンド**であり、その選択はアプリが読むことも設定することもできるアドレスに
出てこない。ここから書けば、名指しできないバンドに当たることになる。

URX44V での実測: LOW / MID / HIGH をそれぞれ別の深さのリダクションへ追い込み (メーターが
-10 / -4 / 0 dB を示す状態) でこの値を立てると、**MID だけ**が効かなくなり LOW はリダクションを
続けた。アプリが最後に書いたバンドでもない — その直前に書いたのは LOW である。

同じエフェクトの他の設定はすべて提供する: 3 バンドの Threshold / Ratio / Attack / Gain、共通の
Release、クロスオーバー 2 つ、出力ゲイン、そして 1-Knob。

## Multi-Band Compressor の 1-Knob が ON の間、操作者のものは Out Gain だけになる

実機のマルチバンドコンプレッサには、エフェクト全体を 1 つの数値から設定する **1-Knob**
(On スイッチと Level) がある。COMP・EQ 画面の 1-knob と同じく、どちらも提供し、どちらも書き込む。

ON にすることは編集ではなくプリセットである: 実機はこのエフェクトの他の全ての値をタイプ固有の値で
埋め直し、OFF に戻しても設定されていた値は戻らずそのままになる。URX44V での実測で、他の全ての値を
元の位置からも互いからも離して arm した状態で ON 遷移を行うと、そのすべてが動いた — 3 バンドの
Threshold / Ratio / Gain / Attack、共通の Release、クロスオーバー 2 つ、出力ゲイン。

以降の Level 変更は、そのうち 1 つを除くすべてを再表明する: 9 個は Level から再計算され
(**各バンドの Threshold / Ratio / Gain**)、6 個は上書きされていても固定値へ引き戻される
(**3 本の Attack・共通の Release・クロスオーバー 2 つ**)。ノブが ON の間、プランナーはその 15 個の
書き込みを止め、調整画面も同じ行をロックする。

**例外は出力ゲインである。**ノブはこれに一切触れないので、プランナーは書き込みを続け、行も操作可能なまま
残る。URX44V での実測: 再計算されない 7 個をノブ ON の**後**にプリセットから離して書くと、7 個とも値を
受け取り 3.2 秒のポーリングでも保持したが、Level を動かすと 6 個が戻り、出力ゲインだけが書いた値を保った。

## Pitch Fix の MIDI Control が ON の間、Scale と 12 音は実機のものになる

Pitch Fix の **MIDI Control** は、補正が狙う音をどこから取るかを選ぶ。**Setting** 以降はそれが実機自身の
USB-MIDI ポートから届き、モードを ON にすると 12 音マスクが消去され Scale 列挙も Custom へ落ちる
(URX44V で実測)。

セレクタ自体は提供し、書き込む。書き込まないのは、モードが Off 以外の間の Scale と 12 音である: それらを
書けば、実機が行ったばかりの消去の上へ操作者の変更前マスクをそのまま戻すことになる。調整画面も同じ 2 行を
ロックし、モードが Off へ戻ると同時に両方とも解放する。

## CUE (ソロ/モニタ割り込み) の割当は制御できない

実機の各チャンネルは **CUE** ボタンを持ち、押すと CUE Bus 経由でそのチャンネルを
モニタへソロ的に割り込ませます。プランナーではこの **CUE Bus への割当 (どのチャンネルを
CUE するか) を表現せず、実機へも反映しません**。CUE のルーティングは電源 OFF で削除される
一時的な Bus であり、保存する計画として永続的な割当を保持できないためです
([device-model.md](device-model.md) 参照)。

MONITOR Bus の **CUE Int** (CUE 割り込みの有効/無効) は確定パラメータで、対応して
います。制御できないのは個々のチャンネルの CUE オン/オフ (割当) です。

## 実機制御の検証は URX44V のみ

実機制御は実機の **URX44V** で開発・検証しています。**URX44** は URX44V の制御
マップをそのまま流用しており (ハードウェア差は HDMI 入力のみで、既定ではルーティング
されません)、一致する想定ですが実機での検証はしていません。**URX22** は、CONSOLE の
ライブメーターのルーティングを URX22 オーナーが実機で確認済みです (ステレオチャンネルの
メーターはステレオペアの位置でインデックスされ、URX22 は mono チャンネルが 2 本のみのため
先頭ステレオチャンネルが CH3/4 になります)。ただし制御 (書き込み) マップと工場初期プランは
依然 URX44V からの類推で未検証のため、値が実機と完全には一致しない可能性があります。
オフラインのプラン作成・プラン JSON・画像
出力には影響せず、対象はこの2機種の Live sync のみです。

**動作確認環境。** 実機制御は以下の組み合わせで確認しています。将来のファームウェアや
Device Center のアップデートで制御プロトコルが変更される可能性があるため、新しい
バージョンでの同一動作は保証されません。

| 構成要素 | 確認バージョン |
| --- | --- |
| 機種 | URX44V |
| ファームウェア | V1.3.1.0 |
| Device Center | 2.2.1 (2.2.1.1) |

## AUTO (オートゲイン) トリガーは非対応

実機の入力画面には、入力ゲインのワンショット自動測定を実行する **AUTO** ボタンが
あります。プランナーではこれを非対応としています。これは保存される設定ではなく
ライブのアクションであり、保存プランやスナップショット差分で表現する対象が無いため
です。入力ゲイン自体は従来どおりプラン・同期できます。対象外なのは自動測定の
トリガーのみです。

## SD Rec の Track Count はソフトウェアから設定できない

microSD レコーダーのトラック毎ソース割当は通常の書き込み可能な設定です
(各ステレオトラックペアがソース — チャンネルペア・STEREO・MIX Bus — を選択・
param 736。[device-model.md](device-model.md) 参照)。

レコーダーの **Track Count** (2 … 16) はアプリから書き込みませんが、理由は
「実機が拒否するから」ではありません。**実機は書込みを受理し、実際に反映します。**
足りないのは値域のほうです。Track Count は param 839 に *value × 2* で載るため
2 … 16 トラックは値 1 … 8 ですが、**broker が公開する最大値は 1 で、それを実際に
強制します** (2 / 4 / 8 はいずれも拒否)。ソフトウェアから届く値は 1 と 0 だけで、
1 は 2 トラック、**0 は実機の値域の外**にあたり、本体の Track Count 画面が
「どれも選択されていない」状態になります (実機 URX44V で確認)。したがって保存した
プランの Track Count は実機へ書き込みません — 届く範囲にあるのが「2 トラック」と
「実機にとって意味を持たない値」の 2 つしかないためです。

**Live sync 接続中に本体側で Track Count を変更した場合は、アプリに届きます**。実機が
変更を告知しており、アプリは書き込まない param 839 も購読しているためです。プランの
値と、盤面がその値で表示本数を決めている録音トラックスロットが追従します。ただし
環境設定のデバイス範囲が *Scene only* のときは追従しません — Track Count はその範囲が
双方向とも触れないデバイス全体設定のひとつです。

これは URX44 / URX44V のみです (URX22 に microSD 録音はありません)。

## 本体の動作モード (Standard / Simple) は判別できない

URX は初期設定で選ぶ 2 つの動作モード — **Standard** と **Simple** — のいずれかで
動作します。Simple Mode では本体が提供する範囲が目に見えて狭まり、チャンネル/Bus の
表示が簡略化されてスクロールもできなくなります。

**ソフトウェアからはどちらで動作しているか分かりません。** broker が公開する全
パラメータを掃引すると、Standard Mode の実機と Simple Mode の同じ実機とで内容が
一致します (実機 URX44V で確認。モードと表示言語だけが異なる 2 回の工場リセットを比較)。
そのためアプリはどちらでも同じコントロールを表示します — Simple Mode の本体側では
取り上げられている機能についても同様です。

読み込まれている**プリセット**は読み取れるので、本体の `P02` のような表示には
ソフトウェア側の対応物がありますが、モードにはありません。取り上げられた機能に対して
アプリが送った書込みを Simple Mode がどう扱うかは測定していません。

## STREAMING の pre-DELAY メーターは取得できない

ブロックダイアグラムでは STREAMING チャンネルに DELAY の前後 2 つのメーターが
描かれていますが、実機ブローカーが公開するのは **post-DELAY** メーターのみで、
**pre-DELAY** メーターにはアドレスが存在しません (実機 URX44V で確認。かつて
pre-DELAY と考えていたアドレスは CUE Bus のメーターでした)。
そのため CONSOLE の STREAMING ストリップは post-DELAY (出力) メーターのみを
表示し、メーターポイントのセレクタは持ちません。ディレイを設定すると pre/post で
レベル変化のタイミングは確かに異なりますが、実機が pre-DELAY 値を出さないため
表示できません — pre-DELAY レベルに最も近いのは、STREAMING のソースとなる
Bus (STEREO / MIX) 自身のメーターです。

## サンプルレートが定着するのは実機の Follow USB が OFF のときだけです

プランナーの **レート** 設定は実機へ書き込まれ (param 766)、デバイスを再クロック
します。この書き込みが残るのは、実機側の **Follow USB** が **OFF** のときだけです。
Follow USB はどちらがクロックマスターかを決める設定で、両方向とも URX44V で実測
済みです。

| Follow USB | クロックマスター | レート書込の結果 |
| --- | --- | --- |
| **OFF** | デバイス | レートが定着し、コンピューター側がデバイスに追従する |
| **ON** | コンピューター | デバイスは受理してリクロックするが、引き戻される |

Follow USB が ON のとき、実機のパネルはレートボタンをロックしますが、ブローカーは
書き込みを **拒否しません** — 新しいレートを受理して再クロックし (LCD に切り替え中の
ダイアログが表示されます)、約 0.4 秒後にホストのレートが再主張されて元に戻ります
(2 回計測: +53 ms 受理 / +374 ms 巻き戻し、および +38 ms / +398 ms)。結果として、
定着しない変更のために音が一瞬途切れるだけになります。

LCD の切り替え中ダイアログは、この**引き戻される側の再クロック**に固有です。Follow USB
が **OFF** のときのレート書込はダイアログを出さずに再クロックします (3 遷移で観測)。
ただし音声はどちらでも途切れます — ダイアログと音声中断は別事象です。

Follow USB はブローカーのパラメーター (848) として公開されており、読み書きとも可能です。
工場出荷時の既定は ON です。実機が既に動作しているレートを書き込んでも、デバイス側が
無視します。

## HDMI のサンプルレート上限は音声モードで変わる

HDMI 入力のサンプルレート上限は、本体の **HDMI メニュー** (SETUP > Peripheral > HDMI) で
設定するモードに依存します。**2ch モード**は 48 kHz 上限で、**Multi Channels モード**は
192 kHz まで対応し、マルチチャンネル音声をステレオペアへ 8→2 で down-mix します。

このモードは入力信号に追従するのではなく、本体で設定して保持されるデバイス設定です。
ルーティングプランには**意図的に含めない**ため、
プランはモードもモード依存のレート上限もモデル化せず、サンプルレート警告にも反映しません。
なお 8→2 down-mix と、Multi Channels モードで実際に高レート信号が届くかどうかは入力される
HDMI 信号次第で、これらは保存プランからは決まりません。HDMI 入力は選択可能なチャンネル
ソースのままで、8→2 down-mix はルーティングに現れます ([device-model.md](device-model.md) 参照)。

## 本体の時計はコンピューターから設定できない

URX は時計を内蔵しており、microSD 録音の日時はこの時計で記録されます。時計は本体
(SETUP > Date/Time の Date/Time ポップアップ) からのみ設定できます。

本体は **USB 接続したコンピューターの時刻にも同期しません**。デスクトップ版からも書き込めません
— 時計は設定可能な値として公開されておらず、時刻を報告するフィールドへ書き込んでも実際の
時計は変わりません。したがって時計がずれた URX は本体画面で直す必要があり、内蔵電池が
消耗した個体 (画面に "Low Battery" または "No Battery" の警告が出ます) は電池を交換するまで
録音日時が正しく記録されません。

日付と時刻の**表示形式**とタイムゾーンは通常の設定ですが、時計そのものはそこに含まれません。

## タイムゾーンの一覧は都市名が実際と異なる場合がある

本体のタイムゾーン設定は、本体が持つ固定の都市名リストへのインデックスです。URX Router は
名前で選べるようにこのリストを再現していますが、実機と突き合わせて確認できたのは数箇所だけで、
それ以外の項目は実際と異なる都市名になっている可能性があります。

影響は目に見えて、やり直しもききます: 適用後に本体の Date/Time 画面が実際に選ばれた都市を
表示するので、選んだものと違っていれば選び直してください。この値に依存するものは他にありません。

## URX22 には Date/Time メニューがない

URX22 は microSD を搭載しておらず、時計は録音の日時記録のためにあるため、本体に Date/Time
メニューがありません。HDMI ページは URX44V のみの装備です。

## URX 本体はデバイス全体設定をシーンに保存しない

これは URX Router ではなく URX 本体の仕様です。URX Router のプランが (デバイスのシーンと
違って) 何を引き継げるかに関わるため、ここに記載します。

本体の**シーン**は**ミキシング**の設定 — 入力チャンネル処理 (HA・HPF・EQ・ゲート・コンプ)、
send、フェーダーと PAN、MIX / FX Bus 設定、Insert FX、ミュート / ON、チャンネル名 — を
保存し、リコールでそのまま復元します。

URX は以下を**シーン外のデバイス全体設定**として保持するため、本体でシーンを保存・リコール
しても変化しません:

- **MONITOR 1 / 2** のソース・レベル・モノ
- **PHONES** レベル
- **Output** パッチ、**USB output** ソース、**microSD 録音**ソース
- **Streaming** 出力と**オシレーター**
- **サンプルレート**、およびシステム設定 (輝度・USER DEFINED KNOBS・日時)

リコール後に **Monitor のソース**が変わらないのが最も目につく例です。Yamaha のユーザー
ガイドも同じ除外を画面カテゴリ単位で記載しており、SETUP・MONITOR・microSD・STREAMING の
設定はシーンに「保存されない」とあります。

> 実機のシーンとライブ状態を比較して確認しました。

## 長時間のセッション後に Device Center の強制終了が必要になることがある

macOS で、長時間ライブ同期を使った後に Device Center が通常の終了手順で終了しなくなり、強制終了が
必要になることがあります。原因は**未確定**です。

短時間のセッションでは再現しません。ライブ同期を明示的に OFF にしてから URX Router を終了した場合と、
ライブ同期を動かしたまま終了した場合を試し、どちらもハングは起きませんでした。

> 任意に再現できてはいません。
