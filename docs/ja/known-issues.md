# 既知の問題

> English version: [../en/known-issues.md](../en/known-issues.md)

現時点の制限事項の一覧。ルーティング規則の詳細は [device-model.md](device-model.md) を参照。

## CH → FX send の PRE/POST は実機へ反映できない

チャンネルから **FX 1 / FX 2** への send の PRE/POST は、プランナー上では自由に
編集でき (プランが意図する値を保持します)、software から URX へは書き込めません
(この設定は本体の操作パネル (LCD) からのみ変更できます)。そのためライブ同期接続中は
コントロールが読み取り専用になり、実機自身の値を表示します。

**ライブ同期接続中に本体側で PRE/POST を変更した場合は、アプリに届きます**。実機が
変更を告知しており、アプリは書き込まないこのアドレスも購読しているためです。
コントロールは 1 秒程度で追従します。

これを運んでいるのは購読で、同じ形は他でも起こりえます: notify の登録集合がアプリの
発行するアドレスそのものだと、読むだけのアドレスはどの登録にも入らず、実機の告知は
誰にも届かず、値が追いつくのは次の全体読みのときだけになります。その場合も実機にも
プロトコルにも問題は無く、欠けているのは登録だけです。

**CH → MIX** および **FX チャンネル → MIX** send の PRE/POST は通常どおり実機へ
反映できます。

> 背景: CH → FX send の PRE/POST は本体の操作パネルでのみ設定でき、broker は
> software からの書き込みを拒否します。

## CH SETTING の Icon は非対応

実機の CH SETTING には名前・色と並んで **Icon** の設定項目がありますが、プランナーでは
意図的に非対応としています。アイコンは mono チャンネルを含む全ノード種別が broker に
公開していますが、値がどの絵柄を指すかを示さない裸のグリフ ID であるため、対応するには
グリフ一式を実機画面と突き合わせて較正する作業が先に必要になるからです。名前と色は
値がそれ自体で意味を持つため対応しています。

## Multi-Band Compressor の 1-knob が ON の間、その値は実機のものになる

実機のマルチバンドコンプレッサには、エフェクト全体を 1 つの数値から設定する **1-knob**
(On スイッチと Level) がある。COMP・EQ 画面の 1-knob と同じく、どちらも提供し、どちらも書き込む。

ON にすることは編集ではなくプリセットである: 実機はこのエフェクトの他の全ての値をタイプ固有の値で
埋め直し (3 バンドの Bypass もここで解除される)、OFF に戻しても設定されていた値は戻らずそのままに
なる。ON 遷移はそのすべてを設定し直す — 3 バンドの
Threshold / Ratio / Gain / Attack / Bypass、共通の Release、クロスオーバー 2 つ、出力ゲイン (URX44V で確認)。

以降の Level 変更は、そのうち 1 つを除くすべてを再表明する: 9 個は Level から再計算され
(**各バンドの Threshold / Ratio / Gain**)、9 個は上書きされていても固定値へ引き戻される
(**3 本の Attack・3 本の Bypass・共通の Release・クロスオーバー 2 つ**)。ノブが ON の間、プランナーは
その 18 個の書き込みを止め、調整画面も同じ行をロックする。

**出力ゲインは ON にしたときに設定され、その後は動かない。**Level を動かしても変わらないが、ノブが ON の間は
実機自身の画面でも回せない。再計算されない 7 個をノブ ON の**後**にプリセットから離して書くと、
7 個とも値を受け取って保持するが、次に Level を動かすと 6 個が戻り、出力ゲインだけが書いた値を
保つ (URX44V で確認)。プランナーは実機と同じく扱う: ノブが ON の間は出力ゲインも書き込まず行をロックし、プランナーでノブを
ON にすると Level を 0 に、固定値 (各バンドの Attack と Bypass・Release・クロスオーバー 2 つ・出力ゲイン) を
タイプ固有の値にするので、ライブ同期が切れていても行は実機が持つ値を読む。ノブが ON でそこに別の値を持つ
プランは、読み込み時にその値へそろえる。

## Pitch Fix の MIDI Control が ON の間、12 音は実機のものになる

Pitch Fix の **MIDI Control** は、補正が狙う音をどこから取るかを選ぶ。**Setting** 以降はそれが実機自身の
USB-MIDI ポートから届き、モードを変えると実機の画面と同じように Scale と 12 音マスクが動く (URX44V で確認)。

セレクタ自体は提供し、書き込む。Scale も、そのモードで実機の画面が出す一覧から選んで書き込む — Setting では
Chromatic 以外、Real Time では Custom と Single。書き込まないのは、モードが Off 以外の間の 12 音である: それを
書けば、実機が行ったばかりの消去の上へ操作者の変更前マスクをそのまま戻すことになる。調整画面は 12 音の行を
ロックし、モードが Off へ戻ると同時に解放する。

## CUE はライブ同期中だけ操作でき、保存されない

チャンネル・FX チャンネル・MIX Bus・STEREO・STREAMING の **CUE** は、ライブ同期中に
CONSOLE・インスペクタの CUE の行 (と、割り当てた MIDI コントロール) から切り替えられ、実機での操作にも追従します。
**プランには含めません**: 実機は電源 OFF で CUE を消し、シーンにも設定ファイルにも
入れないため、保存したプラン・アンドゥ・画像の書き出しには CUE はどれも入りません
([device-model.md](device-model.md) と [architecture.md](architecture.md) の CUE の記述を参照)。

ライブ同期をしていない間、アプリ内では何も CUE されていません: セッションが終わると CUE を
消し、CONSOLE の CUE のチップも、インスペクタの CUE の行も、CUE に割り当てた MIDI コントロールも切り替わりません。
チップは MIDI ラーンの対象にはなるので、コントロールの割り当てはできます。

モニターが CUE バスを流している間 (何かを CUE していて、その Cue Interrupt が入っている間)、CONSOLE のその
MONITOR のストリップは CUE バスのメーターを示します — **URX44V だけ**です。CUE バスのメーターのアドレスが分かって
いるのはこの機種だけなので、URX22 と URX44 の MONITOR のストリップは、CUE している間もモニター自身の出力を示し続けます。

本体の **CUE Mode** (System ファームウェア V1.5。MONITOR 画面の *Mix CUE* / *Last CUE*) も、同じく
ライブ同期中の状態です。ライブ同期中は、ステータスバーと MONITOR の各ノードのインスペクタが本体の
モードを表示し、切り替えられます。*Last CUE* のときは、本体と同じく、新しく入れた CUE が同じ組の
ほかの CUE と入れ替わります。モードを切り替えると、CUE はすべて外れます (本体が外し、アプリも
合わせます)。モードはプランには含めません: ライブ同期をしていない間、ステータスバーには出ず、
MONITOR のインスペクタの行は押せません。

> URX22 と URX44V (System 1.5.0.1) で確認しました: Last CUE の決まりは 2 台とも。URX44V では、
> 制御接続から書いたモードも確認しました。

## 40〜120 Hz の外の HPF 周波数はデバイスへ書き込めない

System ファームウェア V1.5 から、本体の **[HPF Freq.]** ノブは 20.0〜600 Hz を 60 段で設定できます
(押し込みながら回しても、同じ 60 段です)。
制御接続はノブより狭く、40〜120 Hz の外への書き込みを拒否します。制御接続がこのパラメーターに
ついて公開している範囲も、40〜120 Hz のままです。

そのため URX Router は、プランには 60 段のどれでも持ち、本体が持つ値はそのまま読みますが、
書き込むのは 40〜118 Hz の 20 段だけです。

- **デバイスへ書き込み** は、40〜120 Hz の外の HPF 周波数を送りません。状態行がそのチャンネルを
  名指しし、本体は自身の値を保ちます。
- **ライブ同期中** は、インスペクタの *HPF Freq* が 40〜118 Hz を出します。本体のノブがこの範囲の外へ
  動かした周波数は、表示して追従します。その値へ戻すアンドゥは、セッションが終わるまで保留します。
- **120 Hz は段にありません** (前後は 118 Hz と 125 Hz)。120 Hz を持つプランは 118 Hz で開き、
  以前のファームウェアから 120 Hz を持ち越した本体は 118 Hz として読みます。書き込むと 118 Hz に
  なります。
- デバイスのセルフテスト (`--experimental` で起動したとき) は、HPF 周波数が 40〜120 Hz の外の
  チャンネルがある間は開始しません。その値を元に戻せないためです。

> URX44V (System 1.5.0.1、Device Center 2.3.0) で確認しました。URX22 と URX44 では確かめていません。

## STEREO の Flex12GEQ の 20 Hz より上のバンドはデバイスへ書き込めない

System ファームウェア V1.5 から、出力バス (STEREO・MIX 1・MIX 2) は 4band PEQ の代わりに **Flex12GEQ**
(31 バンドのグラフィック EQ) を使えます。MIX 1 と MIX 2 のバンドは、制御接続からすべて書き込めます。
STEREO で書き込めるのは 20 Hz のバンドだけで、残りの 30 バンドへの書き込みは、左右どちらの側も
制御接続が拒否します。

そのため URX Router は、この 30 バンドを CH → FX send の PRE/POST と同じように扱います。

- プランにはどの値でも持て、セッションが無い間は GEQ 画面で編集できます。
- **デバイスへ書き込み** はこれらを送らず、本体は自身の値を保ちます。
- **ライブ同期中** は、STEREO の GEQ 画面のこれらのフェーダーが読み取り専用になり、本体の値を表示します。
  本体の GEQ 画面で変えた値はアプリに届きます。本体が変更を告知し、アプリは書き込まないこれらのバンドも
  購読しているためです。これらのバンドに割り当てた MIDI のコントロールは、セッションの間は値を受け付けません。STEREO の画面の Gain Flat も
  選べなくなります。平らにするバンドが、制御リンクの受け付けないバンドだからです。

> URX44V と URX22 (System 1.5.0.1) で確認しました。本体の GEQ 画面での変更が告知されることは、URX44V で
> 確認しました。URX44 では確かめていません。

## Console Lock 中は何も書き込まない

System ファームウェア V1.5 で、本体の SETUP メニューに **[Console Lock]** が加わりました。本体はロック中も制御接続からの
書き込みを受け付けるので、URX Router はロックが続く間、自分の書き込みを止めます。アプリから本体をロックしたり、
ロックを外したりはしません。

- **ライブ同期の間**は、盤面の上の帯が、本体がロックされていることを示します。セッションが書く値を変える編集は
  何も送らずに元に戻し、プランに入らない書き込み (CUE・CUE Mode・ステレオチャンネルの表示側・本体設定・Follow USB) は
  断ります。どちらも状態行で知らせます。何も書かない編集 (ノードの移動・メモ・色) は、そのまま通ります。ロックが
  来たときに送っていなかった分は本体から読み直し、ロックが外れても送りません。送るには、もう一度編集します。
- **ライブ同期の外**では、本体へ書き込む・本体設定の適用・Follow USB の表示は、ロック中の本体を断ります。書いている
  途中でロックが来たら、次の 1 件で止めます。本体へ書き込むは、どこまで送ったかを知らせ、ロックが外れてから
  もう一度書き込むと残りが送られます。
- デバイスのセルフテスト (`--experimental` で起動したとき) は、ロック中の本体では開始しません。書き込んだあとで
  ロックに止められたセルフテストは本体を書き換えたままにし、ロックが外れたらデバイスメニューの
  **セルフテストの書き戻し** で元に戻します。その前にアプリを終了すると、書き戻しに要る情報はなくなります。

> URX44V (System 1.5.0.1) で確認しました。URX22 と URX44 では確かめていません。

## 実機制御の検証は URX44V と URX22

実機制御は実機の **URX44V** で開発し、実機の **URX22** でも確認しています。URX22 では、
制御マップを実機から読み取って確かめました: すべての入力ポートの値、すべての D.Gain の
アドレス、入力段の各アドレスが届くジャックと HI-Z を持つジャック (ジャック 2)、ステレオ
チャンネルのブロック、USB OUT とダッカーのキーのセレクタが取るチャンネルのスロット、各
ストリップの [CUE] のフラグ、ステレオのチャンネルが表示する側と LCD 選択のつながり、
常時結線のすべての Send です。Insert FX と FX エフェクトの中の設定値も URX22 の LCD で読み、URX44V で
較正した値・エンコード・範囲と一致しました。工場初期プランも実機と一致します: 工場出荷時の状態に
初期化した URX22 に新規プランを書き込むと、書き込むすべてのアドレスで実機は既に同じ
値を持っています (サンプルレートだけは、Follow USB が ON の間は USB ホストに従います)。
**URX44** は URX44V の制御マップをそのまま流用しており (ハードウェア差は HDMI 入力のみで、
既定ではルーティングされません)、一致する想定ですが実機での検証はしていません。URX44 の
入力段は MIC/LINE のジャックごと・デジタルソースごとに、URX44V のアドレスで書き込みます。
各アドレスがどのジャックに届くか、各 D.Gain のアドレスがどのソースに効くかは未検証の
マッピングとして登録しています (`jack-axis`・`dgain-source`)。それらのアドレスで失敗した
読み書きはそのマッピングを名指し、自己診断は決着できないことと、何が決着させるかを出します。
ステレオのチャンネルが表示する側と実機の LCD 選択のつながりも、URX44 では URX44V の番号付けを使い、`lcd-side` として登録しています。各ストリップの [CUE] のフラグも同じで、`cue-flags` として登録しています。
オフラインのプラン作成・プラン JSON・画像
出力には影響せず、対象は URX44 のライブ同期のみです。

**動作確認環境。** 実機制御は以下の組み合わせで確認しています。将来のファームウェアや
Device Center のアップデートで制御プロトコルが変更される可能性があるため、新しい
バージョンでの同一動作は保証されません。

| 構成要素 | 確認バージョン |
| --- | --- |
| 機種 | URX44V、URX22 |
| ファームウェア | V1.5.0.1 |
| Device Center | 2.3.0 (2.3.0.1) |

## 本体は +48V と HI-Z を同時にオンにできるが、アプリはしない

ユーザーガイド (「INPUT screen」の [+48V] ボタン) は、ファンタム電源と HI-Z は同時に
オンにできないと書いています。URX44V と URX22 (System 1.3.1.0) のパネルでは 1 つのジャックで
両方をオンにできます: [+48V] がオンのまま [HI-Z] を押しても、[HI-Z] がオンのまま
[+48V] を押しても両方オンになり、どちらも相手を切りません。

2 つのスイッチは MIC/LINE のジャックのもので、チャンネルは読んでいるジャックのものを表示するので、
アプリはジャックをそれを読むチャンネルで名指します。アプリは、片方がオンの間にもう片方をオンにすることはありません:

- **インスペクタと CONSOLE。** ジャックの +48V / HI-Z のどちらかがオンの間、
  もう片方の ON は押せません — インスペクタのトグルと CONSOLE のチップは読み取り
  専用になり、ツールチップが先に切る方を示します。点いている方を切る操作はいつでも
  できます。
- **MIDI。** もう片方をオンにする書き込みは拒否され、理由をステータス行に出します。
  何も編集されません。どちらかを切る書き込みは通ります。
- **アンドゥ / リドゥ。** 適用した結果ジャックの両方がオンになる操作は、実行せず
  保留します。ステータス行にそれを読むチャンネルと、破棄していないことを出します。
  どちらかを切れば同じ押下が通ります。実機が報告したままの状態を保つ操作と、
  それ以外を動かす操作は保留しません。
- **プランを開くとき** (ファイル・`?plan=` リンク・ドロップ)。1 ジャックで両方
  オンのドキュメントは、+48V を切り HI-Z を残して開き、読み込みが正規化したほかの
  値と同じくステータス行で報告します。
- **実機の読み込み** (Fetch・ライブ同期の開始・実機追従・`.urxf` の取り込み)。
  両方オンの実機はそのまま取り込み、ステータス行にそのチャンネルを出します。
  アプリはそのために実機へ何も書き込みません。その後どちらかを切ることはできます。
- **実機の読み込み中に押した ON。** 読み込みが着地するまで、アプリは実機が何を
  持っているかを知らないので、その押下を受け付けます。そのジャックでもう片方が
  オンだと読み込みが分かった時点で、アプリが知っていた場合と同じくその押下を拒否
  します: スイッチはオフに戻り、ステータス行にそのことをチャンネル名付きで出し、
  そのスイッチについては何も送信しません。実機側のスイッチはそのままです。
  A.Gain を +40 へ下げた Hi-Z の押下は丸ごと拒否し — A.Gain は実機の値に戻り、
  +40 は送信しません — その押下を再び適用するアンドゥの手順も残しません。同じ間に
  行った、2 つと関係の無い編集は通常どおり反映され、どちらかを切る操作は拒否しません。
  実機がもう片方をオンにしたと通知する前にアプリが送信済みだった押下は実機に届いて
  おり、実機は両方オンになるので、そのまま取り込みます。
- **ライブ同期中、実機のパネルでオンにしたスイッチ。** 実機がそれを通知した時点
  から、アプリはそのジャックのもう片方の ON を送信しません — 押して送信待ちの
  ものと、Hi-Z の押下が一緒に下げた +40 の A.Gain も含みます。アプリは ON を送信
  する直前にもう片方のスイッチを実機に問い合わせるので、その通知がアプリに届く前
  でも同じです。また、その通知の後に
  アプリが決める書き込みが、読み込みがそのスイッチを取り込む前にそれを切ることは
  ありません。その
  通知が始める読み込みは、その間に行った押下を、読み込みの開始前でも最中でも、
  上と同じく拒否します。
- **実機への書き込み。** 両方オンのジャックを持つプランは送信しません。リンクを
  開く前に書き込みを止め、ステータス行にそれを読むチャンネルを出します。実機へは何も
  届きません。どちらかを切れば書き込みは通ります。プランが両方オンを持つのは、
  読み込んだ実機が両方オンだった場合だけで、その状態がプランに入る経路は読み込みと
  `.urxf` の取り込みだけです。どちらかを切るまで画面に残します。実機に反映済みの
  プランを送り直すとき (実機が他の設定をリセットする変更の後にライブ同期が行う
  修復) も、実機がもう片方をオンにしている間は片方をオンに戻さず、実機のパネルで
  オンにしてまだ読み込んでいないスイッチを切ることもありません。

**A.Gain は HI-Z に従う。** HI-Z がオンの間、実機の A.Gain は -8 … +40 dB で、
+40 を超えて書いた値を実機は適用しません。HI-Z がオンの間は、インスペクタの
スライダー・CONSOLE のノブ・MIDI コントロールの全ストロークも同じ範囲になります。
A.Gain が +40 を超えた状態でアプリから HI-Z をオンにすると、同じ編集で A.Gain を
+40 へ下げます (1 回のアンドゥで両方が戻ります)。HI-Z がオンで A.Gain が +40 を
超えるプランは A.Gain を +40 にして開き、+48V の修正と同じく報告します — ジャック・ソース
自身の範囲 (A.Gain -8 … +70、D.Gain -24 … +24) の外のゲインを持つプランも、近い方の端に
して開きます。実機は -8 未満の A.Gain を適用せず、記述子の範囲を超える値は拒否するためです。HI-Z は
A.Gain より先に書き込み、+48V / HI-Z のうちプランが切っている方をもう片方より先に
書き込むので、書き込みの途中で両方がオンになることはありません。

## 実機から取れるのは選択中のステレオ CH の側だけ

実機はステレオ CH ごとに表示する側 (L / R) を持ちますが、伝えてくるのは LCD で選択中の CH の
側だけです。そのためライブ同期の開始時にアプリが実機から取るのはその 1 CH の側だけで、ほかのステレオ CH は
アプリが表示していた側のままとなり、実機の表示と食い違うことがあります。ライブ中は、実機でステレオ CH を
選ぶか側を切り替えるとアプリもその側を表示し、アプリで側を切り替えると実機の LCD の選択がその CH と側へ移ります。

## AUTO (オートゲイン) トリガーは非対応

実機の入力画面には、入力ゲインのワンショット自動測定を実行する **AUTO** ボタンが
あります。プランナーではこれを非対応としています。これは保存される設定ではなく
ライブのアクションであり、保存プランやスナップショット差分で表現する対象が無いため
です。入力ゲイン自体 (MIC/LINE のジャックごとの A.Gain、デジタルソースごとの D.Gain) は通常どおりプラン・同期できます。対象外なのは自動測定の
トリガーのみです。

## SD Rec の Track Count はソフトウェアから設定できない

microSD レコーダーのトラック毎ソース割当は通常の書き込み可能な設定です
(各ステレオトラックペアがソース — チャンネルペア・STEREO・MIX Bus — を選択・
制御リンク経由。[device-model.md](device-model.md) 参照)。

レコーダーの **Track Count** (2 … 16) はアプリから書き込みませんが、理由は
「実機が拒否するから」ではありません。**実機は書込みを受理し、実際に反映します。**
足りないのは値域のほうです。**broker が公開する最大値は 2 トラックで、それを実際に
強制します** (4 / 8 / 16 トラックはいずれも拒否)。ソフトウェアから届く値は 2 つだけで、
1 つは 2 トラック、もう 1 つは**実機の値域の外**にあたり、本体の Track Count 画面が
「どれも選択されていない」状態になります (実機 URX44V で確認)。したがって保存した
プランの Track Count は実機へ書き込みません — 届く範囲にあるのが「2 トラック」と
「実機にとって意味を持たない値」の 2 つしかないためです。

**ライブ同期接続中に本体側で Track Count を変更した場合は、アプリに届きます**。実機が
変更を告知しており、アプリは書き込まない Track Count も購読しているためです。プランの
値と、盤面がその値で表示本数を決めている録音トラックスロットが追従します。ただし
環境設定のデバイス範囲が *シーンのみ* のときは追従しません — Track Count はその範囲が
双方向とも触れないデバイス全体設定のひとつです。

**サンプルレートを上げると Track Count が下がることがあり、レートを戻しても戻りません。**
実機側の上限が 44.1 / 48 kHz で 16 トラック、88.2 / 96 kHz で 8、**176.4 / 192 kHz で 2**
(ユーザーガイドの RECORDER メニュー) で、上限を超えている本数はその上限まで落ちます:

- **88.2 / 96 kHz へ** — 8 を超える設定は 8 になる
- **176.4 / 192 kHz へ** — 2 を超える設定は 2 になる
- **低いレートへ戻したとき** — 落ちた本数のまま

新しいレートの上限以下の本数はそのままです。8 トラックで録音している実機は 96 kHz へ上げても
失いませんが、192 kHz へ上げると 6 本失います。**アプリも同じ片方向の遷移をモデル化しています** —
プランの本数はレートに合わせて下がり、レートを戻しても上がらず、インスペクタはレートが許す本数だけを
提示し、盤面はトラックスロットをそれでゲートし、実機を再クロックする経路は変更前に代償を述べます
(architecture.md)。できないのはトラックを戻すことです。サンプルレートはアプリが書き込むため、これは
すべてアプリ操作から届く経路です。そして上の段落のとおり、**アプリから書ける値では戻せません**。
戻す手段は本体の microSD 画面 → RECORDER メニュー → [Track Count] です。レートを上げる前に、
レコーダー側を一度考えるだけの価値があります。

これは URX44 / URX44V のみです (URX22 に microSD 録音はありません)。

## グラフと CONSOLE は本体の動作モード (Standard / Simple) に従わない

URX は初期設定または SETUP > [Operation Mode] で選ぶ 2 つの動作モード — **Standard** と
**Simple** — のいずれかで動作します。Simple Mode では本体が提供する範囲が目に見えて狭まり、
チャンネル/Bus の表示が簡略化されてスクロールもできなくなります。

本体はモードを公開しており、変化のたびに notify で告知します: Simple Mode に入ってプリセットを
適用すると値が動き、Standard に戻すと元に戻り、ほかのパラメータは動きません。URX22 と URX44V
(System 1.3.1.0) で、SETUP > [Operation Mode] から 1 つのプリセットで Simple に入る経路を
確認しました。Setup Assistant と Scene からの入り方、ほかのプリセットは確かめていません。実験的起動では、アプリはライブ同期中にこれを
読み、notify にも追従して SIM ビューの LCD に表示します (architecture.md「SIM ビュー (本体の LCD)」)。ほかの
面はこれを読みません: グラフ・CONSOLE・インスペクタは、どちらのモードでも同じコントロールを表示
します — Simple Mode の本体側では取り上げられている機能についても同様です。

現在のシーンや**プリセット**も読み取れます (Recall と Store で動きます) が、
モードとは別物で、Standard に戻した後も Simple のプリセットの値のまま残ります。取り上げられた
機能に対してアプリが送った書込みを Simple Mode がどう扱うかは分かっていません。

## STREAMING の pre-DELAY メーターは取得できない

ブロックダイアグラムでは STREAMING チャンネルに DELAY の前後 2 つのメーターが
描かれていますが、実機ブローカーが公開するのは **post-DELAY** メーターのみで、
**pre-DELAY** メーターにはアドレスが存在しません (実機 URX44V で確認)。
そのため CONSOLE の STREAMING ストリップは post-DELAY (出力) メーターのみを
表示し、メーターポイントのセレクタは持ちません。ディレイを設定すると pre/post で
レベル変化のタイミングは確かに異なりますが、実機が pre-DELAY 値を出さないため
表示できません — pre-DELAY レベルに最も近いのは、STREAMING のソースとなる
Bus (STEREO / MIX) 自身のメーターです。

## サンプルレートが定着するのは実機の Follow USB が OFF のときだけです

プランナーの **レート** 設定は実機へ書き込まれ、デバイスを再クロック
します。この書き込みが残るのは、実機側の **Follow USB** が **OFF** のときだけです。
Follow USB はどちらがクロックマスターかを決める設定で、両方向とも URX44V で確認
済みです。

| Follow USB | クロックマスター | レート書込の結果 |
| --- | --- | --- |
| **OFF** | デバイス | レートが定着し、コンピューター側がデバイスに追従する |
| **ON** | コンピューター | デバイスは受理してリクロックするが、引き戻される |

Follow USB が ON のとき、実機のパネルはレートボタンをロックしますが、ソフトウェアからの
書き込みは **拒否されません** — 実機は新しいレートを受理して再クロックし (LCD に切り替え中の
ダイアログが表示されます)、その直後にホストのレートが再主張されて元に戻ります。結果として、
定着しない変更のために音が一瞬途切れるだけになります。

LCD の切り替え中ダイアログは、この**引き戻される側の再クロック**に固有です。Follow USB
が **OFF** のときのレート書込はダイアログを出さずに再クロックします。
ただし音声はどちらでも途切れます — ダイアログと音声中断は別事象です。

Follow USB は読み書きとも可能です。工場出荷時の既定は ON です。実機が既に動作しているレートを書き込んでも、デバイス側が
無視します。

## HDMI のサンプルレート上限は音声モードで変わる

HDMI 入力のサンプルレート上限は、本体の **HDMI メニュー** (SETUP > Peripheral > HDMI) で
設定するモードに依存します。**2ch モード**は 48 kHz 上限で、**Multi Channels モード**は
192 kHz まで対応し、マルチチャンネル音声をステレオペアへ 8→2 で down-mix します。

このモードは入力信号に追従するのではなく、本体で設定して保持されるデバイス設定です。
ルーティングプランには**意図的に含めない**ため、
プランはモードもモード依存のレート上限もモデル化せず、サンプルレート警告にも反映しません。
なお 8→2 down-mix と、Multi Channels モードで実際に高レート信号が届くかどうかは入力される
HDMI 信号次第で、これらは保存プランからは決まりません。HDMI 入力は選択可能なチャンネル
ソースのままで、8→2 down-mix はルーティングに現れます ([device-model.md](device-model.md) 参照)。

## 本体の時計はコンピューターから設定できない

URX は時計を内蔵しており、microSD 録音の日時はこの時計で記録されます。時計は本体
(SETUP > Date/Time の Date/Time ポップアップ) からのみ設定できます。

本体は **USB 接続したコンピューターの時刻にも同期しません**。デスクトップ版からも書き込めません
— 時計は設定可能な値として公開されておらず、時刻を報告するフィールドへ書き込んでも実際の
時計は変わりません。したがって時計がずれた URX は本体画面で直す必要があり、内蔵電池が
消耗した個体 (画面に "Low Battery" または "No Battery" の警告が出ます) は電池を交換するまで
録音日時が正しく記録されません。

日付と時刻の**表示形式**とタイムゾーンは通常の設定ですが、時計そのものはそこに含まれません。

## タイムゾーンの一覧は都市名が実際と異なる場合がある

本体のタイムゾーン設定は、本体が持つ固定の都市名リストへのインデックスです。URX Router は
名前で選べるようにこのリストを再現していますが、実機と突き合わせて確認できたのは数箇所だけで、
それ以外の項目は実際と異なる都市名になっている可能性があります。

影響は目に見えて、やり直しもききます: 適用後に本体の Date/Time 画面が実際に選ばれた都市を
表示するので、選んだものと違っていれば選び直してください。この値に依存するものは他にありません。

## URX22 には Date/Time メニューがない

URX22 は microSD を搭載しておらず、時計は録音の日時記録のためにあるため、本体に Date/Time
メニューがありません。HDMI ページは URX44V のみの装備です。

## URX 本体はデバイス全体設定をシーンに保存しない

これは URX Router ではなく URX 本体の仕様です。URX Router のプランが (デバイスのシーンと
違って) 何を引き継げるかに関わるため、ここに記載します。

本体の**シーン**は**ミキシング**の設定 — 入力チャンネル処理 (HA・HPF・EQ・ゲート・コンプ)、
send、フェーダーと PAN、MIX / FX Bus 設定、Insert FX、ミュート / ON、チャンネル名 — を
保存し、リコールでそのまま復元します。System ファームウェア V1.5 からは、**Output Patch**
(アナログ出力と **USB output** のソース) と、**STREAMING** チャンネルのソース・ディレイのオンと
時間・色もシーンに保存されます。

**Standard Mode** では、URX は以下を**シーン外のデバイス全体設定**として保持するため、本体で
シーンをストア・リコールしても変化しません:

- **MONITOR 1 / 2** のソース・レベル・モノ
- **PHONES** レベル
- **microSD 録音**のソースと Track Count
- **STREAMING** のディレイのフレームレート
- **オシレーター**
- **サンプルレート**、およびシステム設定 (輝度・USER DEFINED KNOBS・日時)

リコール後に **Monitor のソース**が変わらないのが最も目につく例です。Yamaha のユーザー
ガイドは除外を画面カテゴリ単位で記載しており、Output Patch メニューを除く SETUP の設定と、
MONITOR・microSD の設定はシーンに保存されない、とあります。同じ箇所に、**Simple Mode** では
Monitor の設定も必要に応じてシーンに保存される、とも書かれています。URX Router のシーン単位の
保存・読込は、上の Standard Mode の境界に従います。

本体を V1.5 に更新する前にストアしたシーンは、Output Patch も STREAMING の設定も持っていません。
シーンがそれらを保存しなかった頃にストアされたためです。

URX Router は、接続した本体のファームウェアがどれであっても V1.5 の境界に従います。V1.5 より前の
ファームウェアのままの本体では、デバイスの範囲が「シーンのみ」でも Output Patch と STREAMING の設定を
読み書きします。そのファームウェアはこれらをシーンの外に置いています。System ファームウェアが上の
確認バージョンと違う本体には、操作の前に確認を出します (環境設定の「未検証ファームウェア」の警告を
オフにしているときは出しません)。

ライブ同期は、開始時に本体の CUE Mode も読みます。V1.5 より前の本体にはこの設定が無く、開始時の
読み取りを終えられないセッションは始まりません。

URX Router 1.18.6 以前で保存したシーン単位のプランファイルは、V1.5 より前のファームウェアの
境界で切り出されており、開くときもその境界に従います。画面のプランの出力パッチと STREAMING の
設定は、保存した当時と同じく、そのまま残ります。それより後のバージョンで保存したプランファイルは、
シーン単位かどうかにかかわらず、URX Router 1.18.6 以前では開けません。

> Standard Mode・System 1.5.0.1 の URX22 と URX44V で確認しました。
