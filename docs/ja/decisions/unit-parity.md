# Decisions: matching the unit's own screens

> English version: [../../en/decisions/unit-parity.md](../../en/decisions/unit-parity.md)

本体の LCD のシミュレーターを作っている間に、アプリを本体の LCD と画面ごとに並べて見比べた。そこから
出た、閉じた判断を置く。アプリが、本体に無いものを出していた所と、本体が持つ状態を違う形で出していた所。
今のアプリの動きは、下に挙げるプルリクエストと、[architecture.md](../architecture.md)・
[known-issues.md](../known-issues.md) にある。下の「操作者」は、このプロジェクトの作業を指示し、決める人の
こと。

どの件も、1 本の線で決まった。**本体の画面に無いものは出さない。本体が持つ状態は、本体が持つ形のまま
表す。** 採らなかった案は、もう提案しない。

## The FX strip's EFFECT face

**決定 (2026-09-21、[#494](https://github.com/semnil/urx-router/pull/494))。** FX チャンネルの EFFECT ON を、
アプリから外した。EFFECT の面は、点灯した見た目のまま、操作できなくし、理由を言うツールチップを付ける。

**採らなかった案。**

- (a) 薄く描く、読み取り専用の面。
- (b) ポップオーバーを開く面。ブランチに一度実装した。
- (c) 面を置かない。

**選ぶ前に、操作者に示したこと。** 点灯は、どの値にも対応しない定数になる。CONSOLE では、操作できない
チップは、ほかでは減光して描いている。そして、「入」でないのに点灯している面は、意匠の中での琥珀の意味から
外れる。操作者は、これらを知ったうえで、点灯の面を選んだ。スクリーンリーダー向けの形は、今ある読み取り
専用のチップと同じ。

## A USB output's MONO IN pair is two wires

**決定 (2026-09-21、[#495](https://github.com/semnil/urx-router/pull/495))。** USB 出力のモノのペア
(CH 1/2・CH 3/4) は、ふつうの配線 2 本で表す。リンクしたペアから引くと 2 本が同時に出る。モノの
チャンネル 1 つから引くと、引いた 1 本が出る。どちらの側も、単独で消したり足したりできる。

- **2 本は、常にプライマリ、相方の順で書く** (`CH n/n+1`)。例外は作らない。
- **3 本目は拒む。** 文言は USB 出力に合わせた。
- **本体の一覧に無い組** (逆の順など) を本体から読んだときは、未読のままにする。

**採らなかった案。** 接続にフラグを持たせ、ソースを切り替えるボタンを付ける形。

## The input stage sits on the jack and the source

**決定 (2026-09-21、[#590](https://github.com/semnil/urx-router/pull/590))。** D.Gain は、入力ソースの値。
+48V・A.Gain・Clip Safe・HI-Z は、ジャックの値。チャンネルには、そのソースとジャックの値を出し、ほかに
何がそれを共有しているかを 1 行で添える。

**採らなかった案。** 入力ノードへ行くボタンだけを出す形。CONSOLE と MIDI に、合わない所が残る。

**同じ日に決めた細部。**

- ソースが None のチャンネルは、ゲインの操作子を消して、詰める。
- ステレオのチャンネルは、片側ずつ出す。どちらの側かは、本体の HOME の画面と同じく、名前の欄で選ぶ。
  極性の操作子は 1 つ。電源の状態は、どのストリップでも LED で出す。LED の当たり判定は、まわりまで使う。
- 出している側は、本体と両方向でそろえる。URX22 と URX44 も同じ決まりで、未検証として登録する。
- CONSOLE では、共有していることを、ツールチップだけで言う。
- MIDI は、チャンネルを id で指したまま、出ている側に効く。
- **編集は、ミキサーのチャンネルでだけ行う。** 入力ノードには、INPUT の操作子を置かない。
- 読んでいないジャックとソースは、書かない。読むのは、どれも読む。
- URX22 と URX44 の D.Gain は、URX44V の表で、未検証として登録する。
- **HI-Z を、チャンネルの名前で書かない。** ジャックの値で、どのジャックが持つかは機種ごとに違う
  (`HI_Z_JACKS`)。チャンネルの名前で書いたままだったコメントと文書は、
  [#629](https://github.com/semnil/urx-router/pull/629) で直した。

**後で反転したこと。** 細部の 1 つは、「Clip Safe の状態のチップは出さない」だった。2026-10-17 に、操作者が、
その状態を CONSOLE とインスペクタにも出すと決めた
([#659](https://github.com/semnil/urx-router/pull/659)。出し方は、実際の画面で比べてから決めた。SIM
ビューの LCD は [#651](https://github.com/semnil/urx-router/pull/651) から出している)。

## Pull requests that carried the rest

同じ見比べから、さらに 4 つの変更が、それぞれ別のプルリクエストで出た。もう 1 つは、別のプルリクエストに
足した。

- [#501](https://github.com/semnil/urx-router/pull/501): デバイスの読み出しが失敗したら、取得とライブ
  同期を止める。モデルを切り替えるのは、読み出しがそろったときだけ。
- [#502](https://github.com/semnil/urx-router/pull/502): STREAMING のソースは、本体と同じく、常に 1 つ。
- [#503](https://github.com/semnil/urx-router/pull/503): +48V と HI-Z を、同時に入れない。HI-Z の間は、
  A.Gain に上限を掛ける。
- [#578](https://github.com/semnil/urx-router/pull/578): 取得やライブ同期がデバイスの機種へ切り替える
  ときも、非表示にしたノードを保つ。
- [#579](https://github.com/semnil/urx-router/pull/579): ソースを既に持つ入力へ別のソースを引くと、
  置き換える。ここに足したこと: ソースを 1 本だけ受ける入力に 2 本を残す項目と、STREAMING を 0 本にする
  項目は、アンドゥが断る。

CONSOLE のゲインのノブに出す、読み出しが失敗したときの印と、MIDI のウィンドウが「今は効かない」と言う
形は、入力段ができてから描いて決めることにしていた。どちらも #590 に入っている。
