# Decisions: the race harness

> English version: [../../en/decisions/race-harness.md](../../en/decisions/race-harness.md)

ライブ同期のレースのハーネス (`e2e/race/`) について、閉じた判断と、ケースを書いて分かったことを置く。
ハーネスそのもの (不変条件・疑似デバイスの契約・ティア・所見) は
[live-race-harness.md](../live-race-harness.md) にあり、変更が守る決まりは `AGENTS.md`「Development」と
「Conventions」にある。この文書は、そこに無い理由を持つ。下の「操作者」は、このプロジェクトの作業を指示し、
決める人のこと。ケースを足す前・書き換える前、シャードの重みを導出し直す前、最初の節に並ぶことを提案する
前に、ここを読む。

## Decisions the operator made

**決定。** 次の項目は、操作者と決めた。新しい根拠が無ければ、もう一度は提案しない。

- **機種の軸は URX44V と URX22。URX44 は足さない。**
- **ティアを短くするのは、シャードの重み付けで行う。ケースを減らして行わない** (2026-08-15)。ハーネスの
  壁時計は、一番遅いシャードで決まる。重なったケースを消しても、動くのは機械の時間だけになる。速さの
  ためにケースの数は減らさない。重みの仕組みは live-race-harness.md の「シャードの大きさの決め方」にある。
- **測って却下した変更が 3 つある。**
  - `scripts/race-shard-weights.mjs` が 1 つのログに掛ける複数の走査 (`durations`・`skippedInLog`・
    `runShape`・`doubledInLog`) を、1 本にまとめる変更。このスクリプトの壁時計は `playwright --list` の
    起動が占めていて、走査は時間の掛かっている所ではない。
  - 同じスクリプトの、シャードごとの `planProblems` の起動を並列にする変更。手で走らせる道具で、レビュー
    していた差分の外だった。
  - 資産のチェッカーの環境変数の分類に、「代入の形」か「参照の形」を求める変更。誤った検出が、必須の
    チェックを赤にする側に出る。
- **単純化のレビューの 8 項目は、操作者が決めた**: アドレスのキーを整数に詰める。フォーカスの復元を
  `src/ui/dom.ts` の `preserveFocus` に集める。spec ごとに繰り返していたロケータを集めるために
  `e2e/race/ui.ts` を作る (「spec は自分だけで完結する」という前の決まりを変えた)。Insert FX がスロットで
  ぶつかるプランは、拒否せずに警告して開く (壊れたファイルと、対応していない版は、拒否のまま)。
  `readIntoPlan` の中の 2 回目の diff を削り、報告は残す。`planProblems` を `src/core/plan-validate.ts` へ
  分ける。スロットの集計は、`insertFxCensus` で描画ごとに 1 回にする。`PLAN_VERSION` を 2 に上げる。
- **CPU を絞るオプションは、ハーネスに残さない。** 負荷を掛けてケースを動かす必要があるときは、ブラウザの
  CPU の絞りを設定する数行を、その調査のために書いて、終わったら消す。
- **どのケースも走らせない疑似デバイスの操作面は、削除する** (2026-08-06)。
- **コールバックがページの側へ渡る経路 (`evaluate`・`evaluateHandle`・`waitForFunction`・
  `locator.evaluate`・`evaluateAll`) を機械で走査する常設の検査は、作らない** (2026-08-13)。その日の走査は
  手作業で、`e2e/` と `scripts/` の、シリアライズされる側だけを見た。モジュールの束縛への参照は、ほかに
  見つからなかった。罠そのものは live-race-harness.md の「ハーネス側で学んだこと」にある。

**覆す条件。** 常設の検査については、足す提案に、それから何が変わったかを添えること。

## One rung per boundary in the MIDI ladders

**決定 (2026-08-17)。** MIDI のはしご 3 本から、6 件のケースを削った。削ったのは、残した段が既に示して
いる境界の、余分な標本だけで、引退した主題は無い。どの段を削ったか、残した段がなぜ境界を示せるか、何を
払って何を得たかは [#412](https://github.com/semnil/urx-router/pull/412) にある。操作者が決めたことで、
削った段はもう一度は提案しない。

## Rungs placed from the app's constants

**決定。** 段は、spec の中の 1 つの定数から相対で置く。その定数は、ソースが export していれば import する。
していなければ、ソースの定義を指すコメントを置く。窓を短くしたときに、前の値を直値で持っていたケースに
起きたことは [#367](https://github.com/semnil/urx-router/pull/367) にある。ハーネスの境界を `DEBOUNCE_MS`
と `IDLE_FULL_MS` に結び付けた掃引は、残した場所とその理由も含めて
[#582](https://github.com/semnil/urx-router/pull/582) にある。この掃引は閉じていて、やり直さない。

- **`RECONCILE_DEBOUNCE_MS` は、必要な場所が無い間は export しない。** `e2e/race/t5-drop.spec.ts` の
  2 か所が、今も `+ 300` と書いている。
- **窓の縁からの余裕は、窓に対する割合でなく、絶対の時間で決める。** 位相のブラケットの残差は、開発機で
  0〜1 ms だった。300 ms の窓の中で安全だった ±10 ms の余裕は、50 ms の窓の中でも同じだけ安全になる。
  ドライバ自身の往復 (約 5 ms) が窓に対して小さいかも、同じ理由で確かめる。

**理由。** 定数が動いたときに落ちるケースは、直される。高くついたのは、緑のまま、何とも比べなくなった
ケースだった。1 つは、対照にしていた段を失い、もう 1 つは、境界そのものの上に乗っていた。

## Pins whose specification changed

**決定。** pin が示している挙動が仕様でなくなったら、新しい挙動を示すように pin を書き換える。セレクタを、
今一致するものへ指し替えるのは、直しにならない。

**実害の記録。**

- MIDI コントロールが、パネルから独立のウィンドウへ移った。「MIDI のパネルは開いたモーダルに数えるので、
  undo は拒否される」を pin していた場所が 2 つあった。`e2e/race/t3-undo.spec.ts` の拒否のはしごと、
  `e2e/race/t0b-sweeps.spec.ts` の掃引である。移動で、これは偽になった。セレクタを新しくするだけにせず、
  逆の主張 (別のウィンドウは何も止めない) へ書き換えた。疑似デバイスも、ウィンドウを覚える必要があった。
  作ること、前面に出すこと、位置と大きさ、2 つのページの間の中継である。ウィンドウがあるかどうかは
  シェルの持つ事実なので、ページごとのフィールドにすると、閉じたページと、聞かれるページで別の値になる。
  それで、`localStorage` に裏付けられた getter にした。中継は `BroadcastChannel` で、送り元には返らない。
  疑似デバイスは `page.context().addInitScript` で入れる。2 つ目のページにも要るからである。
- 既にソースを持つ入力へのドロップが、拒否から、ソースの置き換えに変わった
  ([#579](https://github.com/semnil/urx-router/pull/579))。その掃引のファイルの 2 つのケースが、レースの
  ジョブで赤になった。そこが、2 つが初めて走った場所だった。PR は、開発機ではアプリのティアだけを回して
  いた。2 つ目は別の原因に見えて、同じ原因だった。インスペクタの結線のピッカーは、ドラッグと同じ候補を
  出すので、ソースを持つポートが、そこでも候補になった。

**ここから決まること。** 拒否を挙動に変える PR は、`e2e/race/t0b-sweeps.spec.ts` で、`silent: true` として
登録されたジェスチャと、使えないコントロールの pin を探す。ドラッグの候補は、ピッカーの候補でもある。

## Measuring where it can be measured

**決定。** ケースは、その配置を開いたまま保てるティアに書く。落ちることのないケースは消して、そこで
作り直す。

- **MIDI のメッセージと本体の読みの間の窓は、ユニットのティアでは開かない**
  ([#483](https://github.com/semnil/urx-router/pull/483))。回帰は、読みの最中にミラーが相方へ同じ値を書く
  もので、差分が出ない。ユニットのハーネスでの 4 つの試みは、修正を外しても緑のままだった。Fetch は、
  届いた MIDI を拒否する。follow の読みは数往復で終わり、押下が着く前に閉じる。読みに 0 を返すように
  すると、後に来る全体の reconcile が勝ち、ケースが測るのはその読みになる。状態の行を待つと、欠陥を待つ
  ことになる (patch が落ちた読みは、何も当てず、何も表示しない)。バリアで読みを開いたまま止められるのは
  レースのティアで、判定は書込の台帳から読む。止めた scoped の読みが、どちらのメンバーも巻き戻して
  いないこと、である。
- **ある瞬間に起きることを pin するには、後で同じ結果を出す瞬間も塞ぐ**
  ([#428](https://github.com/semnil/urx-router/pull/428))。配置 (refetch の読みを止め、その内側で全体の
  読みを終わらせる) は作れた。その後、次のジェスチャの前に、止めていた読みを放した。逸脱が予約した
  やり直しの読みが、ほかに何も開いていない状態で終わって報告を消費し、前のガードに戻してもケースは緑の
  ままだった。次のジェスチャを、読みを止めている間に押すようにして、変異が落ちた。配置を作って終わりに
  しない。読みの開始と終了を計装し、判定の瞬間に何が開いていたかを 1 回読んだ。
- **レースのティアで作れない配置は、ユニットのティアで作る。** 本体のリンクは 1 本のキューなので、掃引の
  内側で開いた refetch は、掃引の末尾より先に使い切られる。バリアを 3 つの位置で試し、止められた位置は
  無かった。起動したアプリのユニットのファイル (共通の部分は `src/main.device.test-util.ts`) は、解決
  しない promise を返して、読みを好きな長さだけ開いたままにできる。

## Writing a verdict

**決定。** 判定を書いたら、それを反証する回を別に回す。その回を 2 回行い、落ちることのない判定と、証拠
より広い主張が見つかった。見つかったものは、直すか、撤回した。件数は live-race-harness.md の「ハーネス側で
学んだこと」にある。

その回と、後の修正で分かったこと:

- **全体の読みの本数は、待ちがアイドルの網をまたぐと、2 つの原因を分けられなくなる。** settle が 300 ms、
  アイドルの網が 900 ms のとき、notify の後に 1800 ms 待つケースは、何が起きても全体の読みを 1 回見る。
  「エスカレーションで起きた」と「アイドルの網で起きた」が同じ数になり、調べている routing を変えても、
  ケースは緑のままになる。判定は順序で書く (scoped の読みが、最初の全体の読みの印より前にある。settle と
  idle がこの順を保証する)。または、ユニットテストで、lookup が返すものを見る。時間の窓で切る方法は
  使えない。印に使うアドレスは、全体の読みの終わり近くで読まれるので、読みの開始の代わりにならない。
- **解析に宣言した編集は、ジェスチャがその編集をしなくなったら消す。** 消さないと、不変条件 2 が毎回
  発火する。
- **refetch のケースは、refetch の範囲の外のノードを編集する。** 範囲の中のノードを編集すると、読み戻しが
  編集を上書きすることを測ってしまう。それは、ケースの名前が指す欠陥とは別の欠陥である。
- **「間欠的で、断定できない」は、窓の置き方がまだ見つかっていないだけのことがある。** バリアは、flush の
  送信のループを、ある 1 つのコマンドで止めるのにも使える。n 番目の書込を止め、ループがまだ届いていない
  アドレスに notify を届けてから、放す。
- **カウンタにするか、フラグにするかは、消費する側の数で決まる。** flush には、値のループと名前のループの、
  独立した消費者が 2 つある。片方が消費したフラグは、もう片方から見えない。snapshot の epoch がカウンタで
  あるのは、そのためである。
- **ワイヤを 1 本足しても、書けるアドレスは増えない。**「読みの後に現れたアドレス」のケースは、Insert FX を
  選ぶ。ワイヤで書くと、前提が偽のまま通る。
- **周期のある編集の列は、flush の窓と干渉し、送られるかどうかが位相で決まる**
  ([#592](https://github.com/semnil/urx-router/pull/592))。Up・Up・Down・Down の 4 拍の列では、converge の後に
  開く窓が、毎回、本体が既に持っている値に当たることがある。計装すると、flush は走っていて、何も送って
  いなかった。アプリが止まったのではない。周期のある列の後では、「送られた」を assert しない。固定する
  のは、位相によらないことである。保持の下限、保持の間の切り替えがストリームに出ること、最後の値。

## Writing a pin

**決定。** pin は、2 つの文字列の位置の関係ではなく、コードの性質を示す。書き換えた pin は、4 通りに
当ててから信用する。

**実害の記録。** 疑似デバイスが名乗らない起動フラグを見るユニットのガードは、配置の変更で 3 回破れ、
3 回目は正しい修正で破れた ([#354](https://github.com/semnil/urx-router/pull/354))。性質を示す形に書き換えた。
名前がシリアライズされる側に無く、引数のタプルにあること。答えは、コールバックの最後の引数の名前を
ソースから読んで、たどること。その書き換えは、レビューでさらに 2 回直った。

- **pin の両側を一緒に直す。** コメントを取り除く処理を、「無いこと」の検査にだけ当てていた。「あること」の
  検査は、生のソースを読み続けた。タプルをリテラルに差し替え、同じ行のコメントに定数の名前を書くと、
  通った。取り除く処理は、位置を取る前に、1 回だけ掛ける。
- **ソースから取った識別子は、正規表現に入れる前にエスケープする。** `$` は識別子に使えて、パターンでは
  アンカーになる。`$` で始まる名前は、一致しなかった。

4 通り: 欠陥をコードに戻す (落ちる)。台帳の側をリテラルにして、コメントで偽装する (落ちる)。コールバックの
中のコメントに識別子を書く (通る)。引数の名前を変える (通る)。

## The permanent-skip ledger

**決定。** 台帳 (`e2e/race/skip-ledger.json`) は、何にも守られていないものを数えるためにある。多く数えると、
その目的が壊れる。項目がガードを名指すのは、そのテストが skip の理由そのものに答えるときだけにする。
迷ったら、`unguarded` のまま理由を書く。

**実害の記録。** 2 つの項目が、別の事実に答えるテストを名指していた
([#348](https://github.com/semnil/urx-router/pull/348)。そのレビューが 2 つを見つけた)。サンプルレートの項目に
名指したテストは、レートのロックを自分で立てるので、拒否の分岐を通っていて、ケースが skip される理由は
見ていない。取り消された Fetch の項目は、題にある経路がもう無く、ケースそのものが書けなかった。代わりに
書いた理由も、間違っていた。「何も守っていない」は偽だった。読み戻しが 2 つのスタックを消すことは、
レースのケースが既に assert していた。「観測する手段が無い」と書いた手段は、出荷済みで、同じティアが
使っていた。正しい理由は、「assert は、リリースのときだけ走るティアにある」だった。ガードがユニット
テストでなければならないのは、このためである。

**ここから決まること。** 「何も守っていない」と書く前に、レースのティアを探す。

## Re-deriving the shard weights

**決定。** 台帳の配列は、ケースの集まりが変わるたびに、走行のログから導出し直す。削ったケースを引き算
するのは、応急の手当てである。仕組みは live-race-harness.md の「シャードの大きさの決め方」に、コマンドは
`AGENTS.md` にある。

- **ログは、このチェックアウトが集めるケースを測ったものでなければならない。** ケースのキーは、ファイル・
  行・題である。ブランチが `main` より遅れている間に、spec のコメントが 1 行動くと、キーがずれて、導出は
  ログを拒否する。順序は、`main` を取り込む → push → その push の走行にスクリプトを掛ける → 配列を台帳に
  貼る → もう一度 push。スクリプトは何も書かない。
- **live-race-harness.md の、今の配列を書いた段落には、検査が無い。** 2 世代前のまま残っていたことがある。
  配列を動かすコミットで、英語と日本語の段落を一緒に直す。
- **台帳の配列を、リテラルで参照する pin を書かない。** `scripts/shard-weights.test.mjs` のフィクスチャが
  前の配列を持っていて、関係のない導出し直しで落ちた。
- **スクリプトは、自分が最良として導出した分け方を、退けることがある。** 切れ目が直列のブロックの内側に
  落ちると、Playwright はブロックごと動かすので、案と、ランナーの割り当てが食い違う。台帳に入れるのは、
  ランナーが届く分け方である。
- **Playwright を上げる PR は、新しい版のシャードのフィルタを、前の版と比べる。** 重みの変数は、Playwright
  の型のある公開面に入っていない。重みが何を数えるかは、版の間で変わったことがある (skip と宣言された
  ケースを、シャードに数えるかどうか)。検査と導出は、走るケースを数える。

## Design decisions closed during the fixes

**決定。** ハーネスが導いた修正を行う間に決まったこと。もう一度は提案しない。

- **恒久の skip の理由は、このリポジトリの台帳 (`e2e/race/skip-ledger.json`) の 1 か所に置き、ほかの文書に
  写さない** (2026-08-11)。理由が切れたとき、写しは読み直されない。ハーネスが走るのは、版上げの PR だけ
  である。台帳の検査が何をするかは `AGENTS.md` にある。
- **プランの側だけでのマージは、劣化だった。** 読みは、使った複製を返す。capture は、形をライブのプラン
  から、値を複製から取る。
- **follow の 3 種類の読みは、ファイルの操作を拒否しない。** この読みは自分で始まる。利用者が始めて
  いない読みのために File > New が何もしないのは、ライブの現場で一番困る。プランの差し替えは、読みの側で
  解く。
- **MIDI も、follow の読みの間は拒否しない。** 拒否すると、1-knob のドラッグの途中で卓が途切れ、マウスの
  操作と違う動きになる。
- **reconcile の間の拒否は、履歴の項目を失わせる。この取引は受け入れた。** 本体に届いたかが運で決まる
  編集より、目に見える拒否を採る。「拒否は何も失わせない」が成り立つのは、refetch の読みだけである。
- **拒否は、項目を閉じる前に判定する。** 先に閉じると、拒否された押下が、読みの途中のプランを焼き付け、
  やり直しがそれを本体へ押し返す。
- **プランの検証は、`loadFromText` の 1 か所で走る。** Fetch・Live 同期の開始・follow の reconcile・設定
  ファイルの取り込みは、検証を通らない。この非対称は意図したものである。

反証の回が見つけた、見落としていた 3 つの形:

- 同じ意味の状態を 2 つ持つと、片方だけ古くなる。背景の読みのカウンタと、その読みの集合があり、中断は
  集合を空にできるが、カウンタは減らせなかった。集合の大きさだけを使う。
- 拒否された分岐は、何も起きなかった分岐とは限らない (上の、閉じる順序)。
- 何も言わずに早く戻る関数は、呼び出し元に成功を報告させる。早く戻ったプランの読み込みが、最近の一覧に
  足され、「開いた」と報告されていた。
