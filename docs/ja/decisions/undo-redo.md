# Decisions: undo and redo

> English version: [../../en/decisions/undo-redo.md](../../en/decisions/undo-redo.md)

アンドゥとリドゥ ([src/ui/history.ts](../../../src/ui/history.ts)) について、閉じた判断を置く。仕組みは
[architecture.md](../architecture.md) の「アンドゥ / リドゥ」と、その中の「1 エントリの範囲」「パッチ」
「拒否する条件」「macOS の Edit メニュー」「キーボード割り当て」にある。この文書は、何を選び、何を採らず、
途中で何が起きたかを持つ。下の「操作者」は、このプロジェクトの作業を指示し、決める人のこと。

## What undo covers

**決定。**

- **対象はプランの全体。** パラメーター、結線、そして位置・非表示・ノート・名前・色。パラメーターだけに
  絞らない。
- **アプリの画面の中での入口は、キーボードだけ。** ツールバーに Edit メニューを足すのは後の話で、そのために
  `canUndo`・`canRedo`・`undo`・`redo`・`menu(kind)` を、キーの処理から分けて公開してある。
- **本体を操作したことでプランに入った値は、履歴に積まない。**
- **本体から来た値は、キーごとに baseline へ吸収する (`absorb`)。`rebase()` は読み戻しのときだけ。**
  `rebase()` は、開いているエントリを落とし、待っている確定も取り消す。本体を触っている間にアプリで
  行った編集が、黙ってアンドゥできなくなる。読み直しも、直接の通知も、`absorb` を通す。MIDI の側は
  [#554](https://github.com/semnil/urx-router/pull/554) で `rebase()` をやめ、MIDI での編集も、ほかの
  編集と同じく履歴に入る。
- **`absorb` は、記録済みのエントリの入れ子の葉も畳む**
  ([#476](https://github.com/semnil/urx-router/pull/476))。条件は、前の像と後の像の両方が、読みを取った
  ときの値を持っていること。前の像だけを見る版は、操作者自身の履歴の値を本体の値で置き換えた。その例は
  プルリクエストにある。
- **プランを書く経路は、`onChange` を通す。** アンドゥを作る中で、通していない経路が 2 つ見つかった。
  グラフの `setNote` と `openNoteEditor` が、ノートの折り畳みの状態を、これを呼ばずに書いていた。ノートを
  開いても、プランは変更済みにならず、本体への書き込みも起きなかった。

**採らなかった案。** 既にある差分の仕組みを使い回す案。ライブの層の差分は本体のアドレスの空間で動き、
そこには位置・ノート・非表示が無く、対応を逆にたどれない。クライアントの差分は、本体を読む。全体の
スナップショットを戻す形を採らない理由は、architecture.md の「パッチ」にある。

## Gesture boundaries

エントリが閉じる時点は、ジェスチャの種類ごとに違う。表は architecture.md の「1 エントリの範囲」にある。

**採らなかった案。** `note()` の中で、遅らせた確定を吐き出す案。編集の経路は、先にプランを変えてから
`markChanged()` を呼ぶ。吐き出す時点で、新しい編集は既にプランに入っていて、エントリが両方を巻き込む。

## A drag is a press that moved

**決定。** ドラッグの間はアンドゥを拒む。ドラッグとは、**押下の後にポインタが動いたこと**。

**採らなかった案。** 押下で立てるフラグ。グラフでの配線の選択と E2E は、`pointerup` が続かない
`pointerdown` を送る。フラグが立ったままになり、その後のアンドゥが拒まれ続けた。合成のイベントを
`isTrusted` で除く案も採らなかった。jsdom は trusted なイベントを作れないので、境界のテストを確かめる
手段が無くなる。

## A press is tracked by its pointer id

押下がどう終わるかは、3 本のプルリクエストで決着した。

- **解放が届かなかった押下を、ボタンを押していないホイールやマウスの移動で終わらせるのは、マウスが始めた
  押下だけ** ([#568](https://github.com/semnil/urx-router/pull/568))。最初の版は、どの押下もそれで
  終わらせていた。レビューが、タッチでの実害を示した。指でノードをドラッグしている間にマウスのホイールを
  回すと、アンドゥが通り、指はそのままノードを動かし続けた。ホイールのボタンの状態も、マウスの移動の
  ボタンの状態も、指やペンのことは何も言わない。条件は、「タッチとペンを除く」ではなく、`=== "mouse"` と
  書く。操作者がそう決めた。
- **押下は、ポインタの ID ごとに持つ** ([#583](https://github.com/semnil/urx-router/pull/583)。操作者が
  4 案から選んだ)。履歴も、調整画面も、インスペクタの保留した描き直しも、押下を終えるのは、そのポインタ
  自身の解放、自身のボタン無しのマウスの移動、blur か focus だけ。押下の状態が 1 つだった頃は、指で
  ドラッグしている間のマウスのクリックでアンドゥが通り、ドラッグが 2 つのエントリに割れた。
  **代償は、解放の無い合成の押下が、blur まで残ること。** そのため、`selectWire` と、E2E の手書きの配線の
  選択は、`pointerup` も送る形にした。補助関数を変えない案では、通常の E2E のケースがどれも通ったのに、
  `selectWire` の後の spec では、本物のクリックを挟んでも、ホイール 2 回が 1 つのエントリにまとまった。
  緑一色の結果が、その案を採らない理由を隠していた。
- **ドラッグの終わりを、最後の押下の終わりに結び付けない**
  ([#585](https://github.com/semnil/urx-router/pull/585))。指を画面に置いたまま、解放の届かなかった
  マウスでキャップやプロットを操作すると、ボタン無しの移動でもドラッグが続いた。ドラッグは、始めた
  ポインタを覚え、ほかのポインタが押されていても、そのポインタの解放で終わる。最後のポインタを待つのは、
  保留した描き直しだけ。

## The macOS Edit menu is the app's

**決定。** Edit メニューの Undo と Redo は、アプリが自分で組む。次の 2 点は操作者が決めた。

1. テキスト欄にフォーカスがある間は、メニューの項目は、欄そのもののアンドゥに任せる
   (`document.execCommand`)。
2. メニューのラベルは、アプリの言語に合わせる。

**既定のメニューを使わない理由。** コードは、次のことを前提にしている。既定の Undo と Redo の項目は、
ページに知らせずに、webview 自身の文字のアンドゥを動かす。ページからは、それを知ることも止めることも
できない。項目を灰色にすることもできない。そのため、選べたのは、2 つの項目を消すか、アプリへつなぐかの
どちらかだった。

**つなぐときに要ること。** メニューへ状態の変化を知らせるのは、状態が本当に変わったときだけ
(`notifyDepth()`)。`note()` は編集のたびに、1 回のドラッグで何十回も呼ばれ、知らせは 1 回ごとに
ネイティブの側へ渡る。

## The key probe stays in dev builds

**決定。** [keyprobe.ts](../../../src/ui/keyprobe.ts) は、操作者の指示で、ソースに常に置く。動くのは dev
ビルドだけ。実際の webview でしか答えが出ない問い — キーの組み合わせがページに届くか、欄のアンドゥが
動くか、ネイティブのメニューの項目を押すと何が起きるか — に答える。キーの割り当ては、この道具の単体
テストが固定している。
