# Decisions: CUE

> English version: [../../en/decisions/cue.md](../../en/decisions/cue.md)

本体の CUE (モニターで聞く音の一時的な切り替え) を、グラフ・インスペクタ・CONSOLE・ステータスバー・MIDI で
表示し、切り替えることについて、閉じた判断を置く。アプリがすることは、
[known-issues.md](../known-issues.md) の「CUE はライブ同期中だけ操作でき、保存されない」と、入れた
プルリクエスト ([#605](https://github.com/semnil/urx-router/pull/605)・
[#609](https://github.com/semnil/urx-router/pull/609)・
[#610](https://github.com/semnil/urx-router/pull/610)) にある。この文書は、何を選び、何を採らず、
なぜそうしたかを持つ。下の「操作者」は、このプロジェクトの作業を指示し、決める人のこと。

## CUE is shown and switched during Live sync

**決定 (2026-10-12。実装は #605)。** それより前 (2026-07-28) は、必要が見つかるまで CUE を入れない、と
決めていた。操作者がそれを見直し、次の形で入れると決めた。

| 項目 | 決定 |
| --- | --- |
| 状態の持ち方 | CUE は、ライブ同期のセッションの間だけの状態。プランに入れず、保存もアンドゥもしない。本体も同じ扱いで、CUE は設定ファイルにもシーンにも入らず、電源を切ると消える |
| CUE できるもの | モノのチャンネル・ステレオのチャンネル・FX・MIX・STEREO・STREAMING。本体と同じく、入力の組 (チャンネルと FX) と出力の組 (STEREO・MIX・STREAMING) に分かれ、片方の組で CUE を入れると、もう片方の組の CUE は外れる |
| MIDI | CUE を MIDI の割り当て先に入れる。ライブ同期をしていない間は、CUE を消して Clear CUE も消す。CUE は押せない。ラーンでの割り当ては受け付け、割り当てたコントロールを動かしても何もしない。ライブ同期を始めたら、本体の状態で置き換える |
| グラフ | 経路の外を薄くし、経路上のノード (入力・CUE したチャンネル・モニター) を CUE の色の枠で囲む。「CUE」の札はモニターだけ。CUE したチャンネルから各モニターへ、CUE の色の実線を最前面に引く。線は枠の外側の縁で止め、枠の中に入れない。置き換えられるモニターへの配線は、ソースが STEREO でも MIX でも、薄い破線にする。CUE バスのノードは足さない |
| インスペクタ | CUE を持つノードでは、Color の行の下に CUE の行 (ON / OFF) を置く。ライブ同期をしていない間は押せず、理由をツールチップで示す |
| CONSOLE | CUE のチップを MUTE の右に置き、CUE しているものだけ点く。枠は、CUE バスを聞いている MONITOR のストリップだけ。札は付けず、そのモニターの `C.INT` のチップを CUE の色で塗る |
| 常に出す表示と一括解除 | 何かを CUE している間、ステータスバーの右側、通信状態の表示の左に、CUE しているものの名前と「Clear CUE」を出す |
| 色 | ダーク `#84e3ff` (本体の点灯した [CUE] の色)、ライト `#0b7285`。その上の文字色は `inkOn()` が選ぶ (ダークは黒、ライトは白) |
| PNG・PDF の書き出し | CUE の表示を含めない |

CONSOLE の行は 2026-11-14 に広げた: 何かを CUE している間、STEREO のストリップは CUE バスのメーターを示し、
専用の輪と CUE のバッジを付ける。その決定は [console.md](console.md) の「The CUE bus over the STEREO strip」にある。

**実装の中で閉じたこと。**

- **出力を CUE したときの枠は、CUE した出力とモニターだけ。** 上流まで囲む案は採らなかった。STEREO では
  盤面のほとんどが囲まれる。上流は薄くする。
- **STREAMING からの線は、輪のまま描く。** STREAMING はモニターと同じ列にあり、線は右へ出て戻ってくる。
  見づらいときのノードの配置は、アプリを使う人に任せる。
- **グラフの枠の余白は 7px。** 設計のための絵は 10px で描いていて、1 行違いの枠どうしが接した。
- **URX22 と URX44 の対応付けは、未検証として登録する** (`UNVERIFIED_MAPPINGS` の `cue-flags`)。
- **ライブ同期をしていない間の扱いは、2026-10-13 に決め直した。** MIDI についての最初の指示が 2 通りに
  読めた。操作者が、表の 3 点を決めた。ライブ同期中でも MIDI のラーン中でもないときは、CUE を押せない。
  オフラインになった時点で CUE を消し、Clear CUE も消す。始めるときは、本体の状態で置き換える。
- **ペアのリンクで相方へ写るフラグは、アプリの中で模さない。** 最初は、本体が知らせてこないという前提で、
  アプリが自分で写していた。本体は知らせてくるので、写す処理を外し、知らせで追う。

**理由。** 本体は、いくつかの場面で、知らせを出さずに CUE を変える。そのためアプリは、組の決まりを自分で
当てる。その決まりを突き止めるのに時間がかかった。表示は、案を描いて比べて閉じた。どちらも、開け直すと
同じ作業をやり直すことになる。

## Whether a scene recall drops CUE is left open

**決定。** シーンのリコールで本体の CUE が外れるかは、調べない。リコールは、値を持たないバルクの
フレームで届き、[follow.ts](../../../src/core/control/follow.ts) がそれを全体の読み直しへ上げる。
CUE のフラグをその読み直しに入れてあるので、本体がどちらの動きをしても、アプリは正しい状態になる。

## The inspector row is repainted, not rebuilt

**決定 (#609・#610)。** グラフからの CUE の切り替えは、インスペクタの行で行う。ノードそのものの上に
操作を置く案は採らなかった。

行は、その場で塗り直す (`syncInspectorCue`)。ライブ同期を始めたときも、同じ行だけを塗り直す。最初の版は、
CUE が変わるたびに `refreshInspector()` でパネルを作り直していて、外部のレビューが不具合を 2 件返した。

- 入力している途中の名前の、末尾の空白が消えた。プランは、名前を正規化して持つ (`normalizeNodeName`)。
- 選択欄にフォーカスがある間は、合成のゲートが作り直しを止め、CUE の行が古いままになった。

セッションの終わりの作り直しでも、同じ形で末尾の空白が消えていた。これは `main` に元からあった。同じ
プルリクエストで直した。`rebuildInspector` は、正規化した結果がプランの値と等しいときだけ、欄の文字列を
引き継ぐ。

CONSOLE の MONITOR のストリップの枠は、最初は内側の `box-shadow` だった。下の FADER / METER の欄の
区切り線がその上に描かれて、枠が切れる。枠を、ストリップの中身より上の `::after` の層へ移した。

## Options that were not taken

どれも、上の決定の前に、アプリの実際の画面に描いて比べた。もう一度は提案しない。

**CONSOLE のチップの置き場。**

| 案 | 場所 | かかったもの |
| --- | --- | --- |
| K1 (採用) | チップの段、MUTE の右 | 後ろのチップが 1 つずつずれる。上の部分 (292px) とフェーダーの部分 (398px) の高さは変わらない |
| K2 | フェーダーの下、数値の上 | フェーダーの部分が 398px から 369px に縮む |
| K3 | 色の付いた見出しの中、名前の右下 | 高さは変わらない。チップが小さい |

3 案は、CUE したチャンネルのストリップにも枠を付けて描いた。その後、枠を MONITOR のストリップだけに
減らした。MONITOR の見出しの右下に「CUE」の札を付ける形を一度採り、`C.INT` のチップを塗る形に替えた。

**グラフでの経路の描き方。** 採った形は D で、それに M1 のモニターの札と、M5 の枠と最前面の線を合わせた。

| 案 | 描くもの | 採らなかった理由、またはかかるもの |
| --- | --- | --- |
| A — ハロー | 配線の下に太い半透明の帯、ノードの下に一回り大きい半透明の面 | 隣り合う 2 つのモニターのハローがつながって見える |
| B — 縁取り | 経路の配線の下に CUE の色の 6px の線、経路のノードに 2px の枠 | 枠の形が、選択と経路トレースが使っている形と同じ |
| C — 破線と札 | 配線の上に CUE の色の破線、CUE したチャンネルとモニターに札 | 破線が、配線そのものの色を隠す |
| D — 経路の外を薄くする | 経路トレースと同じ形。配線 0.16、ノード 0.3、経路に枠 | CUE は入れている間ずっと続くので、盤面の残りがその間ずっと薄い。経路トレースと見た目が重なる |
| E — 札だけ | 札。配線には何もしない | どの入力が聞こえているかを、盤面から読めない |

A・B・D は、札を足した形でも描いた。

**モニターが CUE バスを流していることの表し方。** 5 案のどれでも、置き換えられたモニターへの配線は薄い
破線にしている。

| 案 | 描くもの |
| --- | --- |
| M1 (札として採用) | モニターに札。CUE バスがどこから来るかは描かない |
| M2 | モニターの入力の端子を CUE の色の輪で囲み、横に「CUE」と書く |
| M3 | 聞こえているものの名前を、モニターのノードの中に書く |
| M4 | CUE した各チャンネルから各モニターへ、細い点線 |
| M5 (枠と線として採用) | 経路のノードに枠、最前面に 2.5px の実線。線はノードを避けないので、ほかのノードの面の上を通る。読める名前は隠さない |

M4 と M5 の線の本数は、CUE したチャンネルの数と、CUE Interrupt が入ったモニターの数の積になる。

**常に出す表示の置き場。** ツールバー (表示の切り替えの右) は、混み合うので採らなかった。ステータスバーの
中では、CUE の表示を右端に置く案を採らず、通信状態の表示の左にした。

**ライトテーマの CUE の色。** 合否は WCAG 2.1 の比で、印はまわりの地に対して 3:1、面の上の文字は
4.5:1。文字色は APCA の Lc で選び、床は 60。ΔE は、ソース選択の配線の青との差 (CIE76)。

| 案 | 色 | 線と枠 対 キャンバス / ノード | 文字 対 面 | 文字の Lc | 判定 | ΔE |
| --- | --- | --- | --- | --- | --- | --- |
| L1 | `#0a7ea4` | 3.62 / 4.04 | 4.63 | 77.1 | 合格 (余裕が小さい) | 34.5 |
| L2 | `#0c8599` | 3.40 / 3.79 | 4.35 | 75.1 | 不合格 (文字) | 46.5 |
| L3 (採用) | `#0b7285` | 4.36 / 4.87 | 5.59 | 82.8 | 合格 | 45.3 |
| L4 | `#6741d9` | 4.92 / 5.50 | 6.30 | 85.8 | 合格 | 48.1 |
| L5 | `#d6336c` | 3.61 / 4.03 | 4.62 | 76.1 | 合格 (余裕が小さい) | 82.0 |
| L6 | 線 `#0b7285`、面 `#84e3ff` | 4.36 / 4.87 | 13.41 | 81.8 | 不合格 (面が地に対して 1.14) | 45.3 |
| L7 | `#32a1b5` | 2.38 / 2.66 | 3.04 | 62.3 | 不合格 (線・面・文字) | 49.5 |

L1 は仮の値だった。ソース選択の配線の青と明るさが近く、縁取り (B) と破線 (C) では配線と見分けにくかった。
ダークテーマの色は、どの項目も通る (キャンバスに対して 12.92、文字は 13.41、Lc 81.8)。
