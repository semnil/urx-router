# Decisions: the SIM view

> English version: [../../en/decisions/sim-view.md](../../en/decisions/sim-view.md)

SIM ビューについて、閉じた判断と、その周りで起きたことを置く。SIM ビューは、本体の LCD を、GRAPH と CONSOLE の
隣に出す画面で、埋め込んだシミュレーター urx-lcd-sim が描く。仕組みは [architecture.md](../architecture.md) の
「SIM ビュー (本体の LCD)」にある。書き込みを断るときの規則は、`CLAUDE.md` の「Conventions」(「A write is refused
only for a reason the unit or the operator gives」) にある。下の中身の多くは、リンクした PR に既にある。そのため、
ここの節は、見出しと結論とリンクだけのことが多い。`lcd-sim#N` と書いた PR は、
[urx-lcd-sim](https://github.com/semnil/urx-lcd-sim) のもの。下の「操作者」は、このプロジェクトの作業を指示し、決める
人のこと。SIM ビューが書くもの、閉じておくもの、シミュレーターの取り込み方を変える前に、ここを読む。

## Decisions of 2026-10-12

設計は、1 回の対話で決めた。決定の全体の理由は 2 つある。2 つのリポジトリを、並べて保守できる形に保つ。既にある
書き込みの経路 (ライブ同期・追従・アンドゥ) を、1 つのままにする。

| # | 決定 | 決めたことと、却下した案 |
| --- | --- | --- |
| D1 | 値の経路 | GRAPH・CONSOLE と同じ。SIM ビューでの編集はプランを変え、実機へはライブ同期が書き、実機の変化は追従がプランへ入れる。却下した案: ライブの接続に乗って、実機へ直に書く |
| D2 | 載せ方 | 同じ文書に載せる。iframe は使わない。ガラスは shadow tree の中に描き、中の起点は、プロパティを初期値から始める。最初の形は CSS の `@scope` だった。レビューで、ページの側の規則が中の要素に当たると分かり、改めた |
| D3 | シミュレーターの外枠 | 出さない。アプリが既に持つものは、外から渡す: 機種、接続の状態、保存できないという知らせ |
| D4 | 表示倍率 | 既定は 100%。切り替えは View メニューの節に置き、どのビューでも出す (D11) |
| D5 | Initialize | 出さない。File > New が、その役をする。却下した案: Device メニューか File メニューの節として置く |
| D6 | シミュレーターの取り込み方 | 下の「How it is taken in」 |
| D7 | 「外部依存ゼロ」 | 「外部」は、このプロジェクトの持ち主自身のリポジトリの外を指す。文言は `CLAUDE.md` の「Tech stack」にある |
| D8 | フォントのライセンス | 同梱する IBM Plex Sans (OFL) を、今あるライセンスの画面に 1 項目として足す |
| D9 | 模擬の機能 | 軽くすることは、目的にしない。模擬の部分を、実機と共通の 1 つのインターフェース (パラメータ・レベル・操作・時計) に改めた。アンドゥに支障が無いことを条件に、承認された。下の「What undo requires of the embedding」 |
| D10 | ガラスの後ろの盤面 | 2 つのテーマで同じ。ダークテーマの盤面に、`color-scheme: dark` を付ける。周りの枠は、テーマに従う |
| D11 | ビューごとのメニュー | ビューによって隠す項目は無い。Arrange・Hide unused・SIM の倍率の節は、どのビューでも出す |
| D12 | 読み上げの名前 | シミュレーターの読み上げの名前を、このアプリの読み方 (C H・slash・dot・Phase) に合わせる。画面の表示は変えない |

実装で変わった点が 2 つある。値は、プランとシミュレーターの間を、パスの単位で行き来する (`PlanTransport` と
[src/core/sim-map.ts](../../../src/core/sim-map.ts))。最初に描いた、デバイスのアドレスを通す形ではない。
シミュレーターは、値を人の読む単位で持っていて、プランの値に近い。もう 1 つは、E2E の読み上げの名前の検査。
shadow tree の中まで見る形に直した。直す前は、SIM ビューの名前を 1 件も読んでいなかった。

**名前の付け方** (2026-10-12): クラスの名前と属性は、ビューごとに挙動をまとめて切り替えることがある前提で、
接頭辞を決める。architecture.md の「SIM ビュー (本体の LCD)」の「名前」の項にある。

## What undo requires of the embedding

D9 は、アンドゥが動き続けることを条件に、承認された。下は、2 つのコードから読み出した条件で、実装で成り立って
いる。

| 確かめたこと | 条件 |
| --- | --- |
| SIM ビューでの 1 つの操作が、アンドゥの 1 件になる | ビューを同じ文書に載せる (D2)。`.urx-lcd-sim` の中からの `focusout` を、区切りにしない。シミュレーターは、値が 1 段動くたびに描き直し、そのたびに `focusout` が出る。区切りとして扱うと、ドラッグ 1 回が 9 件に分かれた |
| 編集が、1 件が閉じる前にプランへ届く | `PlanTransport` の書き込みは、IPC を待たずに、その場でプランへ入る |
| アンドゥが、SIM ビューで新しい編集を生まない | `PlanTransport` は知らせるだけで、自分からプランへ書かない |
| ドラッグ中は、アンドゥを断る | D2 と同じ。ドラッグは、ほかと同じく、window のポインタのイベントとして見える |
| 1 つの編集が連れていく書き込みが、同じ 1 件に入る | 無し。1 件の差分は、閉じるときに取る |
| 実機からの読みとの調停 | 編集は、CONSOLE と同じファネルから入る |
| アンドゥのキー | シミュレーターの題名の欄にフォーカスがあるとき、キーはプランに何もしない。`ownsNativeUndo` は、shadow tree の中のアクティブな要素を読む |

ここでは、「コードを読んで、支障は見つからなかった」が 1 度外れた。9 件に分かれるドラッグは、読みではなく、
E2E のケースが見つけた。

## How it is taken in

**決定 (2026-10-25、[#728](https://github.com/semnil/urx-router/pull/728))。** シミュレーターは、git の submodule
として取り込む。依存の更新のボットが更新し、自動でマージする。SIM ビューが出す版は、シミュレーターの
チェックアウトのコミット。

**置き換えた前の形。** D6 は、最初、パッケージマネージャーの git 依存で、コミットを固定した。submodule・subtree・
リポジトリの統合は、却下していた。2026-10-22 に、更新を自動にするため、リリースのタグに従う形を試し、同じ日に
やめた。依存の更新のボットは、その種類の git 依存を更新しない。自動の更新は、submodule にして、できるように
なった。

**`pnpm sync:merged` は、submodule のリポジトリを消さない。** submodule を持つ worktree は残し、消すための
コマンドを表示する。削除のたびに、その前に状態を読む。前の形は、「消えると困るものを数え上げて、消してよいと
確かめる」形で、数え上げが閉じなかった。却下した案: 数え上げを続ける。リポジトリを、共通の git ディレクトリの
下へ移して残す。ケースは #728 にある。

## Decisions of 2026-10-14 to 16 (#645)

[#645](https://github.com/semnil/urx-router/pull/645) で、SIM ビューを入れた。そこで閉じたもの:

- **止めるコントロールには、錠前の印と、理由の吹き出しを付ける。**
- **microSD の入口は開けたままにし、中の操作を止める。** 実機が再生している間は、レートを書かない。
- **アプリ自身がレートを書いたとき、HOME の [Sends] の Send 先の読み直しは要らない。** アプリがレートを書くのは、
  接続を持たない Write のときだけ。そのとき、Send 先を持っていない。この項目は、誤った前提で、判断の項目として
  挙げていた。
- **1-knob EQ が ON の間、SIM ビューが書くバンドの値で、プランのバンドを変えない。** EQ の調整画面と同じ。
- **1 つの編集が連れていく 6 つの書き込みのうち、画面の規則は、Day の上限だけ。** 残りの 5 つは、実機が自分で行う。
- **リンクしたペアの名前・アイコン・色・入力ソースは、相方に写らない。**

後で置き換わった #645 の文言がある。SETUP > GENERAL と Follow USB のメッセージは
[#651](https://github.com/semnil/urx-router/pull/651) で、ライブ同期中のレートの変更の拒否は、下の Q5 で。

## Audit of the write restrictions

**決定 (2026-10-17〜18)。** アプリが書き込みを断る所を、1 つずつ、その根拠と突き合わせた。制限を残すのは、本体か
操作者が理由を与えるときだけ。

**残したものと、その根拠。**

- ライブ同期中の Track Count: 操作者の決定と、[device-control.md](device-control.md) の「Track Count is not written」
  に記したこと。
- ライブ同期中の、CH → FX の Send の PRE / POST: CONSOLE を基準にするという操作者の決定と、その書き込みを実機へ
  反映できないこと ([known-issues.md](../known-issues.md))。
- 96 kHz を超えるレートでの FX 2・インサートエフェクト・ステレオ EQ と、+48V と HI-Z を一緒に ON にすること:
  本体の仕様。
- microSD の再生中と、録音の 3 つの状態でのレート: 操作者の決定と、本体の仕様。
- 本体自身の操作 (シーン・カード・録音・再生): 操作者の決定。
- Operation Mode・Software Integration・時計: 書くアドレスが無いか、アプリが書かない。
- Pitch Fix の鍵盤と、1-knob が切の間の M.B.Comp の Level: 本体が値を作る。
- オフラインの CUE: ライブ同期中でも MIDI の Learn 中でもないときは、CUE を押せなくするという操作者の決定。
- デバイスを読んでいる間の編集 ([#507](https://github.com/semnil/urx-router/pull/507))。

**外したもの。** ライブ同期中のレート・Device setup・設定ファイルの取り込み・デバイスの範囲。Sync 中の Delay。
Delay の Note。Pan Link 中の Send の PAN。Pitch Fix の Scale (代わりに、一覧を絞る)。これらには、「同時に書いては
いけない」という操作者の明示が見つからなかった。根拠は、architecture.md に書かれた理由だけだった。

**足したもの。** 上限を超えたインサートエフェクトを外すこと。M.B.Comp の Out Gain。COMP の Attack と Release。

## Lock policy

**決定 (2026-10-18、[#661](https://github.com/semnil/urx-router/pull/661))。** SIM ビューが錠前を描く・コントロールを
減光するのは、**アプリ**にできないことだけ。書かない値、持たない機能、読めない状態。本体自身が、何も出さずに
操作を止める・隠す所は、シミュレーターが、本体と同じものを描く。

**理由。** このビューは、本体を模擬する。COMP の 1-knob が ON の間、本体は、Attack と Release を出したまま、
回さないだけ。そこに錠前の印を付けると、本体が出さないものを出すことになる。#661 で、インサートエフェクトの
スイッチが動かす値・高いレートでの FX 2 への Send・Follow USB が入の間のレートのロックを外した。規則は、
architecture.md の「SIM ビュー (本体の LCD)」の「止めるもの」の項にある。

## Incidents

- **シミュレーターが書くパスが、表に無く、`ui.` の下でもないと、編集が丸ごと取り消される。** シミュレーターの
  store は、全部か無しか。#645 で 3 回起きた。ペアのリンクと SSMCS の分割 (レビューで見つかった)。レートの変更と
  一緒に書かれる再生の状態 (SIM ビューからレートを変えられなかった)。Output Patch のタブ (編集が USB の出力に
  届かなかった)。後ろの 2 つは、カバレッジが未到達と示した行にテストを書いて、初めて見つかった。今は、ビューが
  そのパスを `GLASS_OWN` で持つ ([src/ui/sim-view.ts](../../../src/ui/sim-view.ts))。
- **読み直しを、別の列で走らせた。** HOME の [Sends] の Send 先の読み直しを、CUE の読み直しの横で走らせた。レースの
  ハーネスの、読みの重なりの不変条件を、13 件で破った。実機からの読みは、`cueWrites` の列に載せ、flush と追従の
  読みを待つ。手元でのレースの実行が拾った。
- **テストが、狙った経路を通らずに通った。** 読み直しの失敗のケースで、一部の読みにだけ答え、ほかを空にした。
  セッションが別の理由で落ち、ケースは通っていた。テストの対象の処理を外しても何も落ちないことで、分かった。
  読みの一部だけを断るときは、残りを `unwrittenRead` に委ねる reader を、`bootDevice` に渡す。
- **シミュレーターは、渡された値を、全体の読み直しで外されるまで持ち続ける**
  ([#683](https://github.com/semnil/urx-router/pull/683))。DAW の有無は、セッションの間だけ渡す。セッションが
  終わった後も、シミュレーターの store に残っていた。Software Integration は、DAW があるものとして描かれ続け、
  オフラインなのに、アプリのロックが当たらなかった。今あったケースは、アプリの側だけを見ていた。**セッションの
  間だけ渡す値を足したら、セッションが終わった後の、シミュレーターの store まで見る。** 全体の読み直しは、
  工場出荷の値から組む。最初の版は、LCD 自身の状態 (選んだ CH・バンク・ノブのモード) まで、工場出荷の値に
  戻した。今は、アプリが何も渡していないパスには、シミュレーターの今の値を返す。
- **セッションごとに持つ本体の状態が、開始の失敗の後も残った**
  ([#681](https://github.com/semnil/urx-router/pull/681))。最初の読み出しの後で開始が断られると、後始末が本体の
  状態を消さなかった。セッションが無いのに、LCD が本体のカードを出し続けた。現在のシーン・カーソル・動作モードにも、
  同じ穴があった。**セッションごとの本体の状態を足したら、通常の終了と、開始の失敗の 2 つで消えるかを見る。**
