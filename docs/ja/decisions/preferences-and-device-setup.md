# Decisions: Preferences and Device setup

> English version: [../../en/decisions/preferences-and-device-setup.md](../../en/decisions/preferences-and-device-setup.md)

設定のモーダル 2 つ — 環境設定 ([src/ui/prefs.ts](../../../src/ui/prefs.ts)) と本体設定
([src/ui/device-setup.ts](../../../src/ui/device-setup.ts)) — と、環境設定から開くライセンスのモーダルに
ついて、閉じた判断を置く。それぞれがすることは、[architecture.md](../architecture.md) の「環境設定」
「本体設定 (本体の SETUP > GENERAL)」と、[known-issues.md](../known-issues.md) にある。この文書は、
何を何より選んだかを持つ。下の「操作者」は、このプロジェクトの作業を指示し、決める人のこと。

## Preferences

**決定。**

- **範囲の設定は、別々の 2 項目。** デバイスとやり取りするもの (読みと書きで 1 つの設定) と、プランの
  ファイルに保存するもの。**読みと書きに、別々の範囲は持たせない。** 操作者が、危険の説明を受けたうえで
  選んだ。読みの範囲の外のパラメーターが、既定の値でライブのスナップショットに入り、収束の処理がその値で
  本体を上書きする。
- **入口は、独立の歯車のアイコン。** 文字の字形ではなく、インラインの SVG で描く。名前は「環境設定」で、
  設定ファイルと紛れないようにした。
- **変更は、すぐに効く。** ボタンは「閉じる」だけ。
- **診断 (照合・セルフテスト・prepare) は、範囲にかかわらず、常に全体を対象にする。** それを言う文は、
  experimental のときだけ出す。
- **シーンの範囲のファイルの読み込みは、マージ。** ファイルが持たない値はそのまま残る。本体でのリコールと
  同じ意味。同じ機種のファイルだけを受け付ける。
- **当てはまらない行は、隠さずに無効にする。** その行に、破線の「デスクトップ版のみ」のピルを付ける。ピルは
  減光しない。デモのビルドでは、アプリケーションのバージョンの節は「今すぐ確認」だけを隠し、バージョンの
  表示として残す。
- **最近使ったプランの行も、ブラウザのビルドで施錠する行に入れる。** モックには無かった。デスクトップ版に
  だけある。
- **「今すぐ確認」は、モーダルを閉じない。** 結果は、バージョンの横に出す。モーダルを閉じるのは、更新を
  受け入れてダウンロードへ進むときだけ。
- **閉じ方は、外側のクリックと Esc。** そろえるために、MIDI のウィンドウにも Esc を足した。
  **更新の確認が飛んでいる間は、閉じる手段をどれも施錠する。** 「閉じる」は無効にして減光し、外側の
  クリックと Esc は何もせず、描き直しは保留する。結果の出る場所が必ずあり、連打が積み重ならない。
  タイムアウトが、必ず施錠を外す。
- **ライセンスのモーダルも、外側のクリックと Esc で閉じる。** 情報を見せるもので、関門ではない。
- **関門になっている 3 つの画面 (同意・ロードレポート・レートの選択) は、Esc も外側のクリックも
  持たないまま。**
- **タイトルと「閉じる」は、常に見えている。** スクロールするのはグリッドの内側。アプリケーションの
  バージョンの節は、最後に置く。

言語とテーマの操作子がどこから来たかは、[ui-design.md](ui-design.md) の「Language and theme live in
Preferences」にある。

## The licenses modal draws its own DOM

**決定。** ライセンスを、iframe で出すのをやめた。[licenses.ts](../../../src/ui/licenses.ts) が、生成した
ページを解析し、アプリ自身の DOM として描く。入れるのはテキストのノードだけで、閉じるときに解放する。

**理由。** モーダルの右端に、白い帯が出ていた。コードは、次のことを前提にしている。デスクトップ版の
webview は、サンドボックスの iframe の右端に、描かれないスクロールバーの溝を取っておき、そこから枠の
背景が透ける。つかめないスクロールバーと、ライトテーマで見えなくなる目印も、同じ内側のスクローラーから
来ていた。スクローラーをメインのフレームの 1 本にすると、これらが無くなり、一覧がアプリのテーマに従う。
枠に配色の宣言を足しても、帯は変わらなかった。

**採らなかった案。** ファミリーを開いた状態で出し、飛び先のチップの行を付ける案。一覧は畳んだ状態で開き、
見出しの行がそのまま索引になる。畳めるなら、チップは要らない。

## Computer sleep

**決定。**

- **抑えるのは、システムとディスプレイ。** 示した 3 つの選択肢のうち、「システムだけ」と「設定で 3 択」は
  採らなかった。効くのはアイドルのタイマーだけで、ふたを閉じたときと、手でスリープさせたときは、
  スリープする。
- **抑えるのは、ライブ同期の間だけ。** 操作者が理由を 2 つ挙げ、これは閉じている。
  1. セキュリティ。アプリを起動しているだけでコンピューターが眠らなくなると、コンピューターが自分で
     ロックしなくなる。ディスプレイを抑えると、アイドルでのロックも止まる。
  2. この機能が要るのは、何も触らずにレベルを見ている場面だけ。

  アプリが動いている間ずっと抑える形は、もう提案しない。セッションへの出入りは、どの経路でも解放を通る。
  起動のときには何も取らない。
- **設定を保存するのは、OS が受け入れた後。** OS が断りうる設定は、これだけ。セッションの外で切り替えた
  ときは、保存するだけで、何も呼ばない。セッションの中で切り替えたときは、すぐに当てる。
- **断られたことは、その行に常にある注記へ書く。** フィールドに持って描き直す形は採らなかった。更新の
  確認が飛んでいる間は、描き直しが何もしないので、知らせが消える。処理はアプリの入口の関数 1 つにあり、
  モーダルへはフックとして渡す。モーダルは、シェルを自分で呼ばない。

## Device setup

**決定。**

- **モーダルにする。** 3 つ目のビューのタブにする案と、モーダルでないパネルにする案は採らなかった。
- **Device メニューのいちばん下から開く。** 手前に区切り線を置く。
- **変更はまとめて当て、操作ごとに接続する。** 変えるたびに書く形は採らなかった。誤った操作が、すぐに
  本体へ届く。このモーダルはリンクを持ち続けないので、開いている間、ほかのデバイスの操作を無効に
  しなくてよい。
- **本体で変えたものには追従しない。** 本体のパネルで変えたものは、モーダルを開き直すと出る。追従には、
  追従の仕組みがこれらのアドレスを知っている必要がある。今のまま登録すると、知らないアドレスとして扱い、
  全体の読み戻しへ上げる。
- **[#666](https://github.com/semnil/urx-router/pull/666) から、ライブ同期の間も開く。** そのときは、
  セッションを通して書く。**オフラインの「本体へ適用」は残す** (2026-10-18)。使う人がはっきり押して行う
  書き込みで、「デバイスへ書き込み」と同じ種類。
- **その項目を持たない機種では、メニューごとに無効にする。隠さない。**
- **機種・シーン・本体の時刻を出すプレートは作らない。** 時計を書き込めない間は、読むだけの表示に意味が
  薄い。**時計を書き込む手段が見つかったら、考え直す。**
- **「バージョン」の節と、「ほかの画面にある項目」の節は作らない。** どちらも、ほかの所で確かめられる。
- **Auto Power Off を短くすると電源が落ちうる、という注記は書かない。**
- **ラベルは英語のまま。** 日本語版のユーザーガイドは、メニューと操作子の名前を英語で書き、説明だけを
  日本語で書いている。仮の訳は当てない。

## Brightness goes down to 0

**決定。** Brightness の下限は 0。本体は 0 を保ち、0 でも LCD はかろうじて読める。下限を 1 にして「0 は
未検証」と注記する形は、操作者の指摘で取り下げた。

**下限が 1 だったときに起きたこと。** モーダルは、読んだ直後の値を、許される範囲へ丸める処理に通す。下限が
1 だと、0 の本体が 1 と表示された。基準の値も下書きの値も 1 で、何も書かれず、画面は何の印も出さずに
本体を誤って伝えていた。この不具合の最初の読み — スライダーだけが丸められ、数値は 0 のまま — は誤りで、
実際の描画を撮って分かった。[device-setup.spec.ts](../../../e2e/device-setup.spec.ts) の 2 つのケースが、
下限を固定している。0 を返す本体は 0 と表示され、もっと明るい本体へ 0 を当てられる。
