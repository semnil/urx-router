# Decisions: external MIDI control

> English version: [../../en/decisions/midi-control.md](../../en/decisions/midi-control.md)

CONSOLE と調整画面のコントロールを、外部の MIDI コントローラーから動かす機能について、閉じた判断と、その周りで
起きたことを置く。仕組みは [architecture.md](../architecture.md) の「外部 MIDI コントロール」に、調整画面のどの行を
割り当てられるかは [channel-tuning.md](../channel-tuning.md) の「MIDI 割り当て」にある。この文書が持つのは結論で、
何を決めたか、何を却下したか、何をもう提案しないかを書く。本体の USB MIDI ポートを制御の経路にしないことは
[device-control.md](device-control.md) にある。下の「操作者」は、このプロジェクトの作業を指示し、決める人のこと。

## The MIDI ports are opened in the shell

**決定。** MIDI の側は、Rust で扱う。使うのは midir (`src-tauri/src/midi.rs`)。機能はデスクトップ版だけにある。
理由は、macOS のデスクトップの webview (WKWebView) が Web MIDI に対応していないこと。ページは、自分でポートを
開けない。ポートの側がシェルにあるので、ブラウザ版とデモ版には、MIDI コントロールが無い (architecture.md の
「外部 MIDI コントロール」の「対象範囲」の項)。

## Wording

- **取り込みモードは `absolute` と `pickup` だけ。** エンドレスエンコーダー向けの `relative` は消した。もう提案
  しない。保存してあるマッピングが `relative` のときは、読み込みで `absolute` へ移す。割り当ては残す。
- **ボタンの動作の名前は、送る側のボタンの種類で付ける。** `edge` が「Momentary」、`state` が「Toggle」。前の名前は、
  受ける側がメッセージをどう読むかを表していて、送る側の名前と交差していた。
- **モードとボタンのモードの選択肢のラベルは、日本語の UI でも英語のまま。** 訳すのは説明だけ。「アブソリュート」の
  カタカナが、前のパネルのセレクトに収まらなかったので、そのときに訳をやめた。
- **GAIN の表記は、今のまま。** 割り当ての一覧は、パラメータの表の `GAIN` を出す。CONSOLE は A.GAIN か D.GAIN を
  出す。操作者は、この不一致を受け入れた。直す対象ではない。

## Echo guard

- **時計で区切る拒否の区間は、持たない** (2026-08-09)。送った後のしばらく、受けたメッセージを断る区間は、長く
  しないと何も守らない。長くすると、本物の操作を捨てる。エコーを防ぐのは、値の一致での判定で、往復の遅れに
  依らない。そのため、最初の送出は、拒否の区間の内側に置かない。もう提案しない。
- **`ECHO_MS` を 300 ms から 50 ms にした** (2026-08-14、[#366](https://github.com/semnil/urx-router/pull/366))。
  窓が、エコーの遅れよりずっと広かった。エコーを返さないコントローラーでは、本物の押下を食っていた。1 打目に
  対して送った確認がガードを張る。`edge` のボタンの 2 打目は、毎回同じ値を運ぶので、窓の中に届くと、エコーとして
  扱われた。`RECENT_MS` は別の定数で、変えていない。

## What goes out at start-up

**起きたこと。** アプリの 2 つ目のインスタンスが、起動のときに、まだ実機から読んでいないプランの値を、1 つ目の
インスタンスが聞いているバスへ送った。ライブ同期中だった 1 つ目のインスタンスは、それをコントローラーの操作
として受け、実機に書いた。

**決定 (2026-08-16、[#410](https://github.com/semnil/urx-router/pull/410))。** 直すのは、送る側。ライブ同期の読み戻しが
落ち着くまで、何も送らない。全体も、差分も送らない。出力を開くのは `liveReadSettled()` で、閉じるのは、
セッションの終わりと、プランの差し替え。一緒に閉じたもの:

- **受ける側でのバーストの検出は、実装しない** (操作者の判断)。1 つの束で届く中身からは、バーストを見分けられない。
  見分けるには、時間の窓が要る。
- **出力が閉じていることは、操作者に表示しない。**
- **取得と、設定ファイルの取り込みでは、出力を開かない。** 代償は分かっている。モーター付きのコントローラーが
  古い位置のまま残り、触ると、取得したプランを上書きする。答えは、pickup のモード。architecture.md の
  「外部 MIDI コントロール」の「フィードバック (MIDI OUT)」の項にある。

**実害の記録: この修正が入れた欠陥が 2 つあり、レビューで見つかった。**

1. ガードが、パスを丸ごと止めていた。パスが早く戻るので、送出と一緒に、受ける側の記帳も消えた。「盤面が動いた
   ので、pickup の係合を外す」が走らなくなった。オフラインで係合したままの pickup は、コントロールが少し動いた
   だけで、その位置をプランに書いた。パスを `feedback(resync, deliver)` に分けて、止めるのは、線と、線を説明する
   2 つのキャッシュだけにした。
2. その分割が、今度は、動いていないアドレスの pickup の状態を、パスのたびに消した。消す処理は、送出に届くことに
   結び付いていた。送出は、送信済みの値のキャッシュで守られている。止められたパスは、そのキャッシュを書かない。
   そのため、比較が成り立たなかった。判定を、盤面の側 (`lastSeen`) へ移した。**「送った」を表すキャッシュを、
   送らない経路の判定に使わない。**

## Instrumentation

**決定 (2026-08-16)。** トレースを書くのは、dev での起動だけ。ビルドのフラグで、リリースに載せる案は却下した。
そこから決まること: パッケージ版は、このログでは見られない。記録する側も、コマンドも、コンパイルのときに落ちる。
dev で見たことがパッケージ版にも当たるかは、仕組みが分かった後に、コードで判定する。計装の場所と使い方は、
`AGENTS.md` の「Reusable assets」にある。

## A window of its own

**理由。** 調整画面は、常に、ウィンドウの幅から 48 px を引いた幅になる。前のパネルは `right: 12px`・幅 360 px に
固定していた。ウィンドウの幅がいくつでも、右端の 348 px を覆っていた。そこは、調整画面のコントロールの列だった。

**一緒に変わったこと。** ウィンドウはビューで、プランを持たない (architecture.md)。`modalOpen()` が数えなく
なったので、**開いている間も、アンドゥは断られない**。`wireDismiss` が当てていた `inert` は、呼ぶ側が無くなった。
Edit メニューのイベントは、メインのウィンドウにだけ送る。MIDI のウィンドウには、履歴が無い。

**実害の記録: レースのスペック。** パネルは、レースのスペック 4 つから操作されている。面を動かした後、1 つの
ブラウザのプロジェクトだけで通ったと報告した。3 つのプロジェクトで、7 件が落ちていた。UI の面を動かす・名前を
変える変更は、`e2e/race/` も確かめる。決まりは `AGENTS.md` の「Conventions」にある。

## Scope

- **ducker は、スコープ `@ducker` を持つ** (2026-09-07)。4 つの値は、スコープの中にある。`duckerOn` は、スコープ
  無しのまま残す。コントロールの id は、保存したマッピングの鍵になる。動かすと、今ある割り当てが切れる。
- **`sub` と `scope` は、まとめない。** gate・comp・ducker で、同じ綴りになったが、別のものとして持つ。`sub` は
  プランの鍵。`scope` は、永続化する id の 3 つ目の要素で、名前空間が違う。
- **バンドはスコープで、カーソルではない。** マッピングは、画面を閉じていても効く必要がある。バンドのバーは、
  画面を開くたびに LOW へ戻る。

## Gang

1 つの物理のコントロールで、同じ種類のコントロールをいくつか動かせる。head は、そのアドレスで最初に learn した
マッピング。head が、フィードバック・pickup の係合・トグルのエコーガードを持つ。受けた値は、メンバーへ配る。
仕組みは、architecture.md の「ソース構成」の `src/core/midi/` の項にある。

**却下した案。** pickup を前処理にする (かえって複雑になった)。メンバーの行の左のレールを、`var(--rail)` の慣習に
寄せる (緑の LED のアクセントは、意図したもの)。マッピングが 1 つだけのアドレスの近道は、残す。フェーダーを
動かすたびに、メッセージごとに通る経路になる。

**実害の記録: 書く順序が結果を決めていた** (2026-09-04。レビュー 4 往復で、1 つずつ出た)。`apply` を `decide` と
`commit` に分けた。gang は、メンバーの目標の値を、メッセージの前の状態から決めてから、書く。それぞれが見えにくかった
理由:

- **メンバーへの適用が、別のメンバーのコントロールを動かす。** リンクしたペアのミラーで起きる。順に書くと、
  2 人目が、1 人目の作った値を読んで、打ち消した。
- **メンバーどうしが、ロックを共有する。** EQ の 1-knob は、4 バンドを計算する。ロックが**外れる**向きは、再試行で
  拾える。ロックが**付く**向きは、持ち主が書いた後では取り返せない。順序を、書く前に決めるしか無い。カタログの
  `governedBy` が宣言する。支配される側を、先に書く。
- **極性は、宣言しない。** 1-knob は、ON の間はバンドを、OFF の間は自分の level をロックする。「支配される側を先、
  支配する側を後、拒否は再試行」の 1 つの決まりで、2 つの向きに足りる。予測は要らない。
- **再試行は、決定をもう一度投入する。決め直さない。** `edge` の目標は、読んだ値の反転。決め直すと、learn の順で
  結果が変わる。
- **鍵は、CH ではなく、ペア。** BAL のリンクは、ノードのパラメータを丸ごと写す。2 つの 1-knob は、1 つの支配する
  側になる。PAN では、CH ごとに EQ と COMP を保つので、正規化しない。

**実害の記録: そもそも誰が書かれるか** (2026-09-04。さらに 3 往復)。ミラーが等しく保つメンバーは、1 つの決定に
畳む (`mirrorId`)。

- **順序を決めるだけでは、足りなかった。** ミラーは、最後に書かれた値に落ち着く。始めの値が食い違うペアは、
  learn の順が決めていた。その状態には、たどり着ける。問題を報告しない保存と読み込みを通る。
- **ミラーが覆う範囲は、ノードとリンクのモードの性質。** パラメータを生成する所ごとに宣言を置くと、どこかで
  必ず漏れる。出来上がったリストへ、まとめて付ける。BAL ではコントロールのすべて、PAN ではインサートエフェクト
  だけ。
- **「何もしない」という決定は、席を保つ。** `button` は、意図して gang にしない。片方が無視する release を、
  もう片方が代わりに行ってはいけない。`decide` の null は、「プランに無い」か「自分宛てではない」を表す。別の
  メンバーが代わりに答えてよいのは、前者だけ。
- **gang の境目は、アドレス。** 1 つの CC は、通常の CC のアドレスと、14-bit のアドレスの両方に届く。ミラーだけで
  畳むと、別の gang のメンバーが答えた。

**実装で、同じ形を 2 回踏んだ。** 最初は、鍵を `mirrorId` だけにした。primary は、自分の id に答えるので、グループに
入っていなかった。次に、席の判定を「id が鍵の全体と等しい」と書いた。鍵が id そのものである間しか成り立たない。
2 つは、非対称な表し方 (secondary だけが `mirrorId` を持つ) に寄りかかった述語だった。頼っている性質を直に問う
形に、書き直した。

## The assignment that never arrived

Learn を ON にしても、MIDI が 1 通も届かないことがあった。原因は、MIDI の層ではなかった。シェルの、ページの
読み込みの後の処理が、MIDI のウィンドウを開いたときに、メインのウィンドウのポートとセッションを閉じていた。
そこから決めた規則は、architecture.md の「セッションの終了処理」にある。

**E2E が届かない所。** スタブのシェルには、本物の webview の、ページの読み込みのフックが無い。2 つ目のページは、
Playwright のページでしかない。ライブ同期中の Learn を、レースのハーネスで再現しても、通った。**網は、Rust の
ユニットテスト。** セッションと、スリープの抑止の持ち主を固定している。今は、PR で `cargo test` が走る。前は、
`src-tauri` をコンパイルする PR のジョブが 1 つも無かった。

## No memo on resolve

**起きたこと (2026-08-29 のレビューで決着)。** `resolve()` は、プランの**オブジェクト**を鍵にして、メモ化していた。
その場での編集では、オブジェクトは変わらない。束縛したコントロールは、インサートエフェクトの family・
プロセッサ・Send を閉じ込めている。ノードがそのエフェクトを手放した後も、メモが答え続けた。書き込みは、
送られないスロットへ行き、操作者がそのエフェクトを選び直した瞬間に現れた。`get()` は、古い値をフィードバックへ
流した。setter だけのガードでは、足りなかった。メモが守っていたのは、もう起きないプランの置き換えで、起きうる
ことは取り逃していた。

**決定。** メモを外した。何が存在するかを知っているのは、カタログだけ。毎回カタログに訊く。消えた id は null に
解決され、呼ぶ側は、それを既に扱っている。外す前に、コストを数えた。bind 22,000 回が、テストの時間 189 ms に
収まる (1 回 9 µs 未満)。`BoundControl` のオブジェクトの同一性に頼る所は無い。`src/ui/midi.ts` に、コメントがある。

## Legend

**決定。** BEHAVIOR の列の凡例は、表の下に、常に印字する。ホバーで出すカードは、もう提案しない。前のパネルで
ホバーのカードが合っていたのは、360 px の帯に置き場が無かったため。独立したウィンドウでは、その前提が無い。
ホバーだけの凡例は、見つけられない操作を持ち込む。

**印字するもの。** 一覧が使っている語彙だけ。マッピングが連続のコントロールだけなら、取り込みモードだけを出す。
マッピングが無ければ、何も出さない。アンバーは使わない。このウィンドウで、アンバーは「割り当て済み」を表す。
2 つの語彙は、`subgrid` で名前の列を共有する。高さは、英語で 290 px、日本語で 241 px、語彙が 1 つのときは 120 px。
コントラストは、注記が 6.15:1、名前が 13.74:1 (2 つのテーマで同じ)。

**実害の記録: パネルをウィンドウにしたとき、凡例が消えた。何も、それを示さなかった**
([#248](https://github.com/semnil/urx-router/pull/248) で戻した)。DOM・CSS・E2E の 2 件が、一緒に消えた。
メッセージの鍵は、参照の無いまま、カタログに残った (型の検査は通る)。消えたことを捕まえるはずのテストは、機能と
一緒に消えていた。`CLAUDE.md` の 1 行だけが、あるヘルパーを凡例と共有している、と言い続けた。

## Where the marks sit

**決定。** 調整画面では、ドットは行のラベルの溝に、リングはコントロールに置く。CONSOLE の置き方は、そのままでは
移らない。これに決めるまでに、3 つを描いた。角の外に置くと、スクロールする列が半分を切る。セルの右上に寄せると、
読み値の最後の文字に重なる。セルの左上に寄せると、値が最小のコントロールで、つまみにちょうど重なる。

## Left unverified

- **物理フェーダーが絶対値の CC を送るタイミング**は、2026-10-10 に「機材が手元に無い」として閉じた (操作者の
  判断)。もう持ち出さない。
- **シェルがポートを開いたまま、フロントの出力ポートが null になったのがいつか**は、再発を待つ (操作者の判断、
  2026-10-10)。**開け直す条件:** 次に、MIDI のウィンドウのポートの欄が、思わぬところで「なし」になっていたら、
  何も操作する前に `midi_open_ports` を読んで、記録する。ポートを開き直すと、その状態は消える。プローブが
  `feedback held — no output port` を残すのは、このため。
